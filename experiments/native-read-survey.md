# Native read surfaces: local survey

Observed 2026-09-16 on macOS, **codex-cli 0.154.0** and **Claude Code 2.1.273**.
Evidence comes from the installed executables: CLI help, Codex-generated protocol
bindings, Claude's embedded control schemas, and actual query responses. No
online documentation was used for these findings.

Reproduce from the repository root:

```sh
pnpm exec tsx experiments/native-read-survey.ts all /absolute/workspace/path
# Or select codex / claude instead of all.
# OAR_CODEX_BIN and OAR_CLAUDE_BIN override the executable.
```

The probe prints JSONL containing versions, response field names, array counts,
and the boolean `rateLimitsAvailable`. It does not print config values, tokens,
account identities, session IDs, conversation text, or raw error messages. The
workspace argument matters: configuration, skills, hooks and plugins can vary
by directory. Runtime startup still loads its normal environment and may run
startup hooks, start MCP processes, refresh caches, or contact services. No
prompt, thread/start, resume, model turn, config write, or approval is sent.
Claude's context query explicitly requests `detail: "summary"`; its embedded
schema says `full` performs per-category token-count API calls, whereas summary
uses previous usage and local estimates. The memory-dialog query itself clears
the runtime's memory-file cache, per its embedded schema. These are native
informational operations, not a promise of a side-effect-free OS process.

## What actually answered

All 21 protocol requests in the probe (including both handshakes), plus the two
Claude CLI commands below, succeeded on the observed installations. This is not
a compatibility guarantee for older binaries or other authentication setups.

| User-facing capability | Codex native surface | Claude native surface | Potential Rao UI |
|---|---|---|---|
| Configuration and origin | `config/read {cwd, includeLayers:true}` → `config`, `origins`, `layers` | `get_settings` → `effective`, ordered `sources`, `applied` (model, effort, etc.) | Project configuration inspector; distinguish configured values from confirmed applied values |
| MCP inventory | `mcpServerStatus/list` → server info, tools, resources, auth status, nullable runtime connection status, tool-discovery error | `mcp_status` → server status, scope, configuration and tools | Servers and tools with actual reported status |
| Skills / commands / agent definitions | `skills/list {cwds}` → skills and load errors | `initialize` → commands and agent definitions; `get_context_usage` → skill frontmatter/source/token metadata | Available capabilities for this workspace; commands are not interchangeable with skills |
| Hooks and permissions | `hooks/list`, `configRequirements/read`, `permissionProfile/list` | `get_hooks_listing`, `list_permission_rules` → rule/source/editability and workspace directories | Explain configured hooks, policy constraints and allowed/denied actions; profiles are not a list of effective rules |
| Context composition and memory | No equivalent category/memory-file read established in this survey; existing token-usage notifications remain useful | `get_context_usage {detail:"summary"}` → categories, memoryFiles, MCP tools, skills, message breakdown, compaction threshold; `get_memory_dialog` → file/folder rows, existence and memory toggles | Context panel with runtime-reported breakdown; dialog rows can include missing files and are not proof all files were injected |
| Additional usage | `account/usage/read` → summary and daily token buckets (37 buckets observed), separate from `account/rateLimits/read` | `get_usage {skip_behaviors:true}` → session totals and native subscription-limit availability; `get_session_cost` → formatted text | Native usage history and session usage; not an inferred billing ledger |
| Native sessions / processes | `thread/list` → native persisted thread metadata; `thread/loaded/list` → this server's loaded threads (empty on the fresh probe server) | `claude agents --json` → active interactive/background processes; `--all` is advertised to include completed background sessions, not tested here | Discover native sessions or active processes; these are different inventories, not a uniform machine-wide live-agent list |
| Plugins | `plugin/list` → marketplace catalogs and plugin metadata, plus loading errors | `claude plugin list --json` → installed plugins, version, scope and enabled state | Plugin panel; marketplace entries do not themselves imply installation or enablement |
| Plan | Not probed | `get_plan` answered with an `exists` field (no plan in this fresh session) | Optional runtime-native plan view; plan contents were not verified |

Additional Codex history methods are present in bindings generated by the
installed CLI: `thread/read`, `thread/turns/list`, `thread/items/list`. This probe
does **not** read conversation contents, so those are schema-confirmed, not
live-verified. Querying history must not be replaced with `thread/resume`, which
activates a session. The observed `thread/list` request sets `useStateDbOnly:true`
to avoid its documented default scan-and-repair path.

Codex bindings were generated both with and without `--experimental`. The
Codex query methods used above appear in both outputs; that only establishes
schema inclusion, not a permanence promise. Some individual fields can still
be experimental. The probe enables experimental API support as the current OAR
adapter does. Example schema generation:

```sh
codex app-server generate-ts --out /tmp/codex-read-schema
codex app-server generate-ts --out /tmp/codex-read-schema-experimental --experimental
```

For MCP, the observed Codex enum is `full | toolsAndAuthOnly`, **not** `summary`.
An initial exploratory `summary` request returned native invalid-request error
`-32600`; the checked-in probe uses `toolsAndAuthOnly` and succeeded. Nullable
`runtimeStatus` must remain unknown when no thread-specific status is available.
Claude's `initialize.agents` lists definitions, while `claude agents --json`
lists running instances. Also, the control request named `background_tasks`
actually backgrounds tasks: it is a mutation and deliberately excluded.

## Consequence for existing OAR usage

At this baseline, `packages/oar/src/runtimes/claude/account-usage.ts` checks CLI
auth, reads persisted credentials (including the macOS keychain), and calls
`https://api.anthropic.com/api/oauth/usage` itself. The newly verified native
`get_usage` control request is a better fit for an OAR boundary that exposes
only runtime-native capabilities.

The local native reply reported `rate_limits_available:false` and
`rate_limits:null`, but still supplied session usage. Switching to that query
would **not** magically enable subscription limits for this login. Nor does
`false` alone establish a particular reason such as expired credentials or an
unsupported auth mode. Preserve the native uncertainty; use a separate native
auth status query only if a more precise diagnosis is required. The embedded
schema marks `get_usage` experimental; an older binary may reject it.

## Suggested order, not an implemented API

1. Replace Claude's direct credential/HTTP usage path with native `get_usage`
   after verifying authenticated subscription, unavailable and older-version
   cases. Preserve the distinction between session usage and account limits.
2. Expose configuration/source and MCP queries; put per-session facts in the
   project inspector and machine/workspace inventories in Dashboard.
3. Add hooks/permissions and skills/plugin inventory without forcing different
   native concepts into one overly broad capability flag.
4. Add Claude context composition and Codex native daily usage as optional
   capabilities. Return their native limitations, not host-generated substitutes.

Session-specific reads must query the existing project's runtime connection.
The fresh process used here proves method availability only: its settings,
context, plan, transient permissions and session usage are not an existing
Rao project's state. Codex config/read is a cwd-aware config view, not proof of
all defaults or transient overrides applied to an already-running thread.

The survey itself added experiments only. Follow-up in 0.3.1: Claude account
usage now delegates to native `get_usage`; see `docs/runtimes/claude.md`. The
old credential/HTTP path described above records the pre-change baseline.
