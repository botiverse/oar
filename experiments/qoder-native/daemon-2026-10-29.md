# Qoder SDK transport migration: 2026-10-29

Qoder CLI 1.1.81 no longer accepts the SDK worker protocol through ordinary
headless stream-json. OAR now uses the official SDK's public daemon entry on
1.1.81 and later, while 1.1.78 through 1.1.80 keep their original launch path.
Each OAR session still owns and cleans up its own process.

## Source evidence

- [src] The published `@qoder-ai/qodercli@1.1.81` bundle rejects
  `--permission-prompt-tool stdio` with `--input-format stream-json`. Removing
  that flag leaves `initialize` unanswered. Its explicit `sdk_worker_removed`
  error says SDK worker sessions were removed, rather than promising backward
  compatibility on that entry.
- [src] The official [`@qoder-ai/qoder-agent-sdk`](https://www.npmjs.com/package/@qoder-ai/qoder-agent-sdk)
  1.0.56 package bundles CLI 1.1.78. Its default process transport still uses
  the old arguments. The public `startDaemon()` uses `--sdk`, daemon protocol
  2, `multi_session_v2`, and `daemon.open_session`. Account-level model queries
  use `daemon.get_models` without `session_id`; session messages carry it.
  These shapes are declared in the package's `dist/daemon/protocol.d.ts` and
  implemented in its distributed JavaScript.
- [src] The native daemon reads local login through the explicit `qodercli`
  auth choice. Unlike the old external-auth replay entry, it requires a local
  identity even with `--fake-responses`. The native credential store uses
  AES-128-CBC with the first 16 machine-id bytes as key and IV. The fixture
  seeds only synthetic, expiring data using that native storage format; the
  installed CLI is unmodified. Explicit environment credentials are cleared
  in the fixture. No real credentials, paid model calls or model binary
  patches are used. Catalog/startup metadata may still use the network.
- [src] The [official release notes](https://docs.qoder.com/release-notes/qoder-cli)
  still stopped at 1.1.80 when checked on October 29. The removal message and
  the published SDK entry, rather than an assumed flag rename, establish the
  migration. No claim of an accidental upstream regression is made.

## Runtime observations

[env] Linux x64, Node 24, isolated installations of each CLI version. Native
vendor tests keep the model provider scripted and exercise the real process,
controls, permission handler, files, MCP clients and session persistence.

The first daemon attempt initialized but failed model confirmation because
`get_models` had moved to the daemon query plane. Moving that private request
to `daemon.get_models` fixed catalog-based confirmation. The native payload
and exact model-name matching are unchanged.

The new path also reports no applied effort for `efficient`, which has no
supported effort levels in the catalog. The effort regression now requests
`ultimate`, whose catalog supports `high`; it still asserts exactly `high`
and a successful turn. OAR does not soften its readback check. An invalid
startup effort remains a refusal whose error names the requested value;
model-confirmation failures are no longer mislabeled as effort failures.

The permission regression uses a native `set_permission_mode` control only
as a stimulus. It observes a real `can_use_tool` request on stdio and verifies
that the marker file does not exist yet. The same production response helper
and transport used by OAR reply to that request; the native tool then writes
the marker and the model turn completes. It does not infer permission support
from an idle session or a bypassed tool call.

The multi-session probe opened two sessions in one 1.1.81 daemon, sent their
first prompts concurrently, matched both successful results to their native
ids, closed the first session, and completed a second turn on the survivor.
This proves basic routing and close behavior on Linux only. It does not prove
cwd/MCP/child isolation, cancellation, background-command cleanup, loaded
resume, race/failure behavior, other platforms, or the resource threshold in
the shared-process design. OAR remains isolated; further evidence belongs to
the shared-process investigation.

The review added forward-compatible handling for unknown connection-wide
frames and an explicit OAR termination reason for a foreign session frame.
Regression tests cover verbatim unknown-frame recording, continued usability,
startup rejection, and the reason retained by records, derived events and the
unfinished turn. No native error frame or turn-end event is synthesized.

## Reproduction

The final adapter passed the following Linux x64 controls on October 29:

| Qoder CLI | Native vendor tests | Shared behavior suite |
| --- | --- | --- |
| 1.1.78 | 9 passed | 17 passed, 2 skipped |
| 1.1.79 | 9 passed | 17 passed, 2 skipped |
| 1.1.80 | 9 passed | 17 passed, 2 skipped |
| 1.1.81 | 9 passed | 17 passed, 2 skipped |

The two skips are the harness's absent account-usage and model-catalog
capabilities; the native catalog and effort readback have separate vendor
coverage. An earlier shared-suite run exposed the missing requested-effort
context in a daemon startup error. The error context was fixed and both
affected version runs passed again without changing the assertion.
The full local check passed 2,363 unit tests and 18 mock behavior cases
(one mock capability skip); both package builds passed. Cross-platform
results belong to the pull request's CI, not these Linux observations.
