# Kimi 2.6.2 and 2.6.3: resumed declarations and workspace registration

November 17, 2026, Linux x64, Node 24.19.0. Local scripted providers and
isolated homes only; no accounts or paid model calls.

The unchanged [direct native probe](native.ts) reproduces the
[2.5.0 finding](2026-11-04.md) on both 2.6.2 and 2.6.3. Each version completed
eight turns across four independently created sessions. A new CLI process
resumes each seeded session. The probe talks ACP directly, without the OAR
runtime adapter. The [selected native evidence](evidence-2026-11-17.json)
contains each supplied server list, provider declaration list, tool result
and ACP prompt result.

| Resume input | Declared to the model, both versions | Actual execution, both versions |
| --- | --- | --- |
| Omitted servers | Initial stdio and HTTP tools | Both old names fail with `Tool ... not found` |
| Empty server list | Initial stdio and HTTP tools | Both old names fail with `Tool ... not found` |
| Same names, new configuration | Initial names | Both tools execute with the new synthetic credentials |
| New stdio and HTTP names | Initial names; new names absent | Old names fail; both new names execute with the new synthetic credentials |

This affects users: the model may call removed tools and cannot discover the
new names from the advertised list. It is not evidence that omitted servers
or their credentials remain active. The renamed controls deliberately call
unadvertised tools; normal model discovery is not established by their
success. ACP returns `end_turn` even when a requested tool failed.

A separate OAR adapter control on 2.6.3 also reproduced the mismatch on
omitted, empty and replacement configurations. The original vendor assertion
still fails because it requires the correct provider declarations. No MCP
assertion or runtime pin changes in this investigation.

## Current source and public controls

The 2.6.3 npm bundle and its exact source tag were inspected. Links below pin
[source commit b0de2fb](https://github.com/MoonshotAI/kimi-code/tree/b0de2fbd2de04d87689225aafd3912e5d193b62d).

- [`resumeAcpSession`](https://github.com/MoonshotAI/kimi-code/blob/b0de2fbd2de04d87689225aafd3912e5d193b62d/packages/acp-server/src/server.ts#L534)
  passes the current MCP input to restore. Omission and an empty array map to
  `undefined`; materialization seeds an empty ephemeral registry in that case.
- [`ToolSelectInitialized`](https://github.com/MoonshotAI/kimi-code/blob/b0de2fbd2de04d87689225aafd3912e5d193b62d/packages/agent-core-v2/src/agent/toolSelect/toolSelectOps.ts#L82)
  preserves the first initial snapshot. Registry reconciliation changes
  `current`, while
  [`capableTools`](https://github.com/MoonshotAI/kimi-code/blob/b0de2fbd2de04d87689225aafd3912e5d193b62d/packages/agent-core-v2/src/agent/toolSelect/toolSelectService.ts#L459)
  falls back to initial entries when a name is absent from the current list.
  Newly connected non-runtime entries do not enter that initial set.
- The inspected ACP configuration switch exposes model, mode and thinking,
  with no tool-catalog reset. The documented experimental on-demand loading
  setting requires a model capability and changes disclosure behavior; it
  does not provide a generic resume-catalog reset. No supported parameter
  that restores ordinary declarations was found in the inspected surfaces.
  OAR does not alter native history or model capabilities to hide the issue.

The earlier 2.5.0 report includes a one-expression diagnostic causal control.
No modified native binary was used for the current results. The report is filed
as [upstream #5036](https://github.com/MoonshotAI/kimi-code/issues/5036) under
Kimi's issue-first contribution rules; its maintainer must approve any proposed
native patch before a PR. The initial decision held the accepted pin pending a
fix. On November 18, that decision changed: both behavior and login CI move to
2.6.3 so newer runtime behavior receives continuous coverage. Versioned vendor
controls now assert the observed stale declarations and failed removed calls,
plus successful same-name replacements. The limitation and issue remain open.
Restore aligned declarations only after a release addressing that issue passes
all four resume variants. An issue closure alone is insufficient.

## Workspace IDs are a separate expectation change

The native
[`POST /workspaces` route](https://github.com/MoonshotAI/kimi-code/blob/b0de2fbd2de04d87689225aafd3912e5d193b62d/packages/kap-server/src/routes/workspaces.ts#L95)
explicitly registers a fresh ID per call. The
[`create` implementation](https://github.com/MoonshotAI/kimi-code/blob/b0de2fbd2de04d87689225aafd3912e5d193b62d/packages/agent-core-v2/src/app/workspace/workspaceService.ts#L133)
reuses only an explicit idempotency key, not the root directory. The separate
[November 16 skill investigation](../runtime-skills-2026-11-16/README.md)
already observed fresh IDs on 2.6.2; this is not a new 2.6.3 defect.

OAR lists existing IDs, removes only a registration it created, and preserves
the user's same-root ID, root and name. The workspace control now reads the
installed native version: the 2.4.1 baseline uses reuse, and versions from
2.6.2 use fresh. Both branches retain the complete user-registration and
cleanup assertions. Removing fixed workflow mode variables lets the daily
candidate use its own version while the accepted pins remain unchanged.
The revised control passed against native 2.4.1, 2.6.2 and 2.6.3. The complete
local check passed 4,799 tests and 19 mock cases. These versioned workspace
results are included in `workspaceControls` in the selected evidence.
Historical failed reuse assertions remain retained and labelled as an obsolete
fixture expectation, separate from the still-failing MCP declaration check.

## Reproduce and limits

Run the same commands as the original report, selecting each exact version:

```sh
node --import tsx experiments/kimi-mcp-resume/native.ts /path/to/kimi-2.6.2 /tmp/kimi-262-resume
node --import tsx experiments/kimi-mcp-resume/native.ts /path/to/kimi-2.6.3 /tmp/kimi-263-resume
OAR_KIMI_BIN=/path/to/kimi OAR_TEST=kimi-skills pnpm vitest run sea-trial/vendor/kimi-skills.vendor.test.ts -t 'discovery preserves an existing user workspace'
```

Full raw files and their manifest stay local. Committed evidence includes
only the fields cited above and substitutes verified labels for synthetic
credential fingerprints. This fresh-process Linux measurement does not prove
same-process restore, changed schemas under identical names, dynamic loading,
or execution behavior on macOS or Windows. Existing daily failures on those
systems establish their declaration mismatch and historical reuse assertion
only, as tracked in [issue 899](https://github.com/botiverse/oar/issues/899).
