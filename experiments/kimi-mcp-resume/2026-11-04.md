# Kimi 2.5.0 MCP resume: stale declarations, current connections

Investigation for OAR task #164, November 4, 2026. Linux x64.

Kimi 2.5.0 retains the **initial tool declarations** across a fresh-process ACP resume. It does not retain the executable MCP tools when their configuration is omitted. The observed daily failure is a mismatch between the provider's tool list and the live tool registry, not evidence that old MCP credentials or connections were restored.

The same native probe on 2.4.1 keeps the declarations aligned with the supplied servers. OAR product code, the existing vendor assertions, and the CI pin remain unchanged.

## Results

Each case creates a native session with a stdio server `echo` and an HTTP server `remote`, calls both successfully, terminates the CLI process, and resumes that session in a new CLI process. The provider is a local scripted OpenAI-compatible endpoint. All credentials are synthetic test markers.

| Resume configuration | 2.4.1 provider declarations | 2.5.0 provider declarations | Actual calls, both versions |
| --- | --- | --- | --- |
| Omit `mcpServers` | No MCP tools | Both old tools | Both old names return `Tool ... not found` |
| Send `mcpServers: []` | No MCP tools | Both old tools | Both old names return `Tool ... not found` |
| Same server names, new synthetic credentials | Both current tools | Both initial tools with the same names | Both calls execute using the new credentials |
| Replace with servers named `newstdio` and `newhttp` | Both new tools | Both old tools; new tools absent | Old names fail; both new names execute using the new credentials |

The last case deliberately makes the scripted provider call names absent from 2.5.0's declarations. This establishes that the new connections and tool registry work. It does not suggest that a normal model could discover those names.

All prompts return ACP `stopReason: "end_turn"`, including those containing tool errors. A successful prompt response therefore does not mean every requested tool executed. No `select_tools` declaration or `<tools_removed>` announcement appeared in these provider requests.

The original daily vendor case already checked the provider declarations. It did not attempt the omitted tools. These new controls add that distinction without changing the original assertion.

## Native mechanism

The installed npm bundles identify themselves as `@moonshot-ai/kimi-code` 2.4.1 and 2.5.0. The following locations are in each version's published `dist/main.mjs`; the source module names are retained in its comments.

1. **ACP conversion is unchanged in the relevant respect.** `acpMcpServersToConfigRecord` maps both omission and an empty array to `undefined`. `resumeAcpSession` forwards the result to `klient.session(id).restore({ mcpServers })` (2.5.0 line 331359).
2. **Connections still use the current restore options.** Session materialization seeds `ISessionEphemeralMcpServers` with `opts.mcpServers ?? {}` (2.5.0 line 127723). The workspace MCP lifecycle returns without an overlay for an empty record and builds a new overlay for supplied entries. Replacing names changes the executable registry as expected.
3. **2.4.1 builds the default declarations from the current registry.** Its `defaultTools()` passes `toolRegistry.list()` through `toolSelect.shapeTools` (line 268001).
4. **2.5.0 adds a durable initial snapshot.** `agent/toolSelect/toolSelectOps.ts` defines durable `tool_select.initialized` and `tool_select.tools_changed` events. Its replayable state separately holds `initial`, `current`, and `changes` (around line 225103).
5. **2.5.0 reconciles the live registry, then chooses the initial declarations.** `createToolSelectResolver` calls `prepareForRequest` before building the request (line 273217). `reconcile` correctly removes the old tools and adds replacement tools in `current`. With dynamic disclosure disabled, `defaultToolsForDisclosure` still chooses `initialTools()` (around line 225650), and its active-entry filter does not require those entries to exist in the current registry.

The isolated native session logs confirm this source reading: omission/empty cases record removal of both MCP tools; replacement records removal of both old tools and addition of both new tools. The provider nevertheless receives the initial pair. The selected JSON includes those durable events without local session identifiers or paths.

## Causal control

A separate, disposable copy of the 2.5.0 bundle changed one expression: the non-disclosure branch of `defaultToolsForDisclosure` selected `currentTools()` instead of `initialTools()`. No other native or OAR code changed.

The same four cases then produced the 2.4.1 declaration sets: empty on omission/empty, current names on replacement. Actual tool execution and credential selection remained unchanged. This isolates the declaration selection as the cause; it is **not** a reviewed upstream fix. Immutable tool lists, prompt caching, and dynamically loaded tools may impose additional native design constraints.

Across the two published versions and that diagnostic copy, the selector verified 24 completed native turns and 54 tool outcomes. Type checking and type-aware lint passed for the probe.

## Persistence and limits

The probe inspected its isolated `KIMI_CODE_HOME` after the runs. None of the four plaintext synthetic credential markers appeared in those files. Durable schema events were present in 2.5.0. This is a bounded observation, not a claim about all native storage locations, encrypted persistence, or production credentials.

These results cover fresh CLI processes, stdio and HTTP MCP, and the local OpenAI-compatible provider with ordinary tool declarations. Same-process restore, real-account models, enabled dynamic-tool disclosure, changed schemas under identical tool names, Windows, and macOS were not tested. No account, paid model, or user home was used.

## Proposed next step

Keep the vendor assertion and current 2.4.1 CI pin until the same controls pass after an upstream fix. The host-visible problem is that omitted tools remain advertised and newly supplied names are missing. A blanket refusal of resumed MCP configuration or a silent filtering workaround in OAR is not justified by these results.

The initial task's phrase “servers retained” should be read as the initial symptom. The refined finding is “initial MCP declarations retained while current MCP connections and execution follow the supplied configuration.”

## Reproduce

Use a checkout containing this probe and install its locked dependencies. The
probe was originally run with the harness at
`b4328cc659fbb231b6941b107ce25d08b3bda261`; both published versions were checked
again after moving it into this directory. It uses the local provider and echo
fixtures without importing an OAR runtime adapter.

```sh
npm install --prefix /tmp/kimi-native-old @moonshot-ai/kimi-code@2.4.1
npm install --prefix /tmp/kimi-native-new @moonshot-ai/kimi-code@2.5.0
node --import tsx experiments/kimi-mcp-resume/native.ts /tmp/kimi-native-old/node_modules/.bin/kimi /tmp/kimi-native-old-results
node --import tsx experiments/kimi-mcp-resume/native.ts /tmp/kimi-native-new/node_modules/.bin/kimi /tmp/kimi-native-new-results
```

Each output directory contains the raw ACP frames, provider requests, stderr, isolated native state, and a summary. Those raw files can contain machine paths and are for local inspection; the selected evidence omits those paths. Synthetic credentials appear only in the reproduction inputs, and the selected evidence labels their verified matches instead of publishing fingerprints.
