# OpenCode v1 and v2 boundaries: 2026-10-09

OAR follows the installed native line under one `opencode` runtime ID.
The v1 `opencode-ai` package and v2 `@opencode/cli` package are independently
maintained; switching lines is a host decision, not an automatic upgrade.

## Native checks

Linux x64, v1 **1.18.35** and v2 **2.0.26**, installed side by side.
[`opencode-release-lines.ts`](opencode-release-lines.ts) used the free
`opencode/big-pickle` model without a provider login or account credentials.
Both lines passed all nine shared boundary checks. A separate v2 concurrent
prompt probe also passed. Each session's complete record
stream and graph were retained locally, including its native frames.

Only session/message/call IDs and the probe directory are normalized.
Replay tests pin attribution, full projected events, native-frame identity,

These defaults belong to the runtime, not to OAR.

## Read-only model listing

Two independent empty OpenCode profiles reproduced the cold-start problem:

- `models --standalone`: exit 0, no stdout or stderr, about 1.4 seconds.
- `api agent.list --standalone`: exit 0, a response naming the probe
  directory with `data: []`, about 0.9 seconds.

The isolated profiles used OpenCode's own `OPENCODE_TEST_HOME` plus separate
XDG config/data/cache/state directories. No existing home or credentials
were changed. The same installation can load a free model through ACP.
Successful emptiness is therefore insufficient evidence that no model exists.

[Upstream issue #53724](https://github.com/anomalyco/opencode/issues/53724)
was already open for 2.0.24; these probes confirm the behavior on 2.0.26.

At source tag v2.0.26 (`9b4ec5714d481559990db0a816d5dec19541a814`),
`packages/cli/src/commands/handlers/models.ts` queries the model list once.
`handlers/api.ts` likewise sends one operation. In contrast,
`packages/cli/src/acp/catalog.ts` waits for plugin activation, then retries
catalog readiness at 25 ms intervals for up to five seconds. This explains
the observed race; it is not evidence of an upstream fix.

OAR uses only `--standalone` for v2 model queries. It neither starts a
persistent service nor creates a temporary native conversation to query
models. Empty output yields `unsupported`, not `ok` with zero models.
Nonempty output can supply the native IDs without invented effort menus.

## Instructions and source boundaries

v2 retains an `instructions` config schema field, but
`packages/core/src/config/plugin/instruction.ts` loads native instruction
files without consuming that field. v1's appended-prompt overlay therefore
silently loses the prompt on v2. v2 also uses `agents.<id>.system` rather
than v1's `agent.<id>.prompt`; v1's `debug config`/`export` resolution path
cannot safely be reused for v2.

Both prompt options are refused on v2, including resume, until OAR has a
verified session-local injection path that resolves the actual native agent.
This does not imply that native OpenCode lacks instruction configuration.
No user config is rewritten or fabricated. v1 prompt handling stays intact.

Native forwarded child updates are defined in
`packages/cli/src/acp/child.ts` and `translate.ts`. OAR reads their explicit
`opencode/child-session` metadata, preserves the real `parentID`, and keeps
all native data. No child is inferred from tool-call-ID string patterns.
The v2 extended child-notification and elicitation capabilities remain
undeclared. Elicitation has no verified host-answer path in this change.

## Steering refusal regression

The shared ACP layer still returns `accepted` when it writes a steering
request. Waiting for the RPC would block v1 steering until the whole loop
becomes idle. A later native refusal produces its error frame with
`input_dropped {inputId, reason: "runtime_refused"}`, returning ownership to
the host without replacing the current turn's outcome.

The regression fixture covers native refusal before and after the original
prompt answer, a refusal arriving during the next turn, and retrying the
same input ID. Grok's native `sendNow` still folds its original interrupted
prompt and replacement prompt as one turn, using the last non-refused
request's outcome. Raw replies and errors remain separate recorded facts.

For the native v2 refusal capture, a probe-only ACP profile sent a second
prompt while a shell call was running. This deliberately bypassed the real
v2 adapter's missing `steer` member. The request was initially accepted;
its native `-32603` error (`data.service: "session"`) then dropped the input
while the original turn stayed running and eventually completed with
ORIGINAL_271. The [captured error](../tests/replay/fixtures/opencode-acp-v2-refusal.json)
drives the simulated ordering tests; only its session ID is normalized.
The first probe invocation used a non-UUID input ID and was refused locally
before sending; the corrected invocation supplies the captured evidence.

A real Grok 1.0.50 steering scenario also passed after the shared change: the
replacement input landed in the same turn and the turn completed. The five
shared behavior backends (mock, Claude, Codex, Pi and Pi Durable with scripted
providers) all passed their applicable cases.

The Grok probe used the existing authorized test login, without a login flow.
Native per-prompt ledgers summed to 77,018 input and 1,033 output tokens,
including 58,368 cached-read tokens. OpenCode probes used no login.
