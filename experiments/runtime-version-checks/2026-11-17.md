11 local login cases and six user/project configuration controls. The
skill observer initially failed because it assumed chunk `993.js`; 1.4.1

and blocks network connections. A dependency upgrade and its platform

### Qoder 1.1.91

The published packages establish the replay boundary at **1.1.82**.
Versions 1.1.78 through 1.1.81 have the `generateContentStream` replay
consumer. Every inspected release from 1.1.82 through 1.1.91 retains
`--fake-responses`, its storage class and configuration method, but no
callers of `getFakeResponseStore` or `getNextResponse` remain. This is not
a renamed flag or changed JSONL response format. Package hashes, counts
and exact source locations are recorded in the JSON.

The initial 1.1.91 replay attempt used a synthetic identity and unexpectedly
reached remote inference, which returned HTTP 500. Both suites were stopped.
That response is not real-account compatibility evidence. The new
[qoder-candidate.ts](qoder-candidate.ts) gate reads the exact native version
first and reports `no_offline_replay_requires_real_account` from 1.1.82,
without launching a replay suite. The complete CI replay stays at 1.1.81.

A separately authorized read-only check in an isolated home reused an
existing login. Native 1.1.91 listed DeepSeek-Flash, and its empty-parameters
check returned the expected error after the account-access guard and before
provider validation. No configuration was created and **zero real model
submissions** were made. This does not establish the account's Free plan
or provider-key availability. The planned text, Read/Write and cross-process
resume round remains pending private credential setup and plan confirmation.
The [manual probe](../qoder-deepseek/README.md) now accepts the source-reviewed
1.1.91 control ordering as well as the earlier 1.1.83 version. Real execution
remains outside CI and will have a separate result.
