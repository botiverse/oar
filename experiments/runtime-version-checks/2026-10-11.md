## OpenCode 1.19.0

The real new binary passed all eight applicable vendor tests in three files,
using temporary homes and local scripted providers:

- MCP over stdio and HTTP on new and resumed sessions, removal when omitted
  on a later resume, user/server name conflicts, and combined prompt options.
- Unknown-model refusal and native auth, rate-limit and billing failures.
- Image-only input reaching the provider without an empty text block.

The separate native prompt-options experiment also passed: replacement
targets the selected agent, appended instructions retain their order, resume
uses the saved agent, deleted agents are refused, and literal prompt text,
model/tool permissions and user configuration are preserved. Temporary-file
cleanup and conflicting configuration refusals passed too.

Eight selected live checks passed on their first attempt using the free
`opencode/big-pickle` model in an isolated home:

| Probe | Result |
| --- | --- |
| Model catalog | `ok`, 11 models |
| Basic turn | Completed; native frames and projected events retained |
| Tool detail | Matching Bash call/result; command and output marker retained |
| Resume | Same session ID and model; recalled `PLUM-42` |
| Concurrent control | Follow-up landed as `steered`; the same turn answered `BANANA` |
| Session MCP | The stdio echo tool ran on both new and resumed sessions |
| Abort during a shell call | `aborted` |
| Dispose during a shell call | `aborted` |

The tool's initial `tool_call_started` has only `cwd`; its later
`tool_call_input` contains the full command. The live probe's
`inputHasCommand: false` describes the start event, not missing input in the
record stream. `usage().total` remains `null`, while `contextUsage()` reports
the current context. No aggregate token count is inferred from that snapshot.

These are selected checks, not a rerun of all 13 historical live scenarios.
Child attribution, direct model switching and the HTTP-server interface were
not re-probed. The unchanged v2 session behavior was not re-tested.

## Upstream changes and limits

The [1.19.0 release notes](https://github.com/anomalyco/opencode/releases/tag/v1.19.0)
announce an opt-in `opencode upgrade --major` migration to v2, OpenAI
`ultrafast` service tier support, PTY validation changes and TUI update
changes. The installed binary's `upgrade --help` advertises `--major` and
says it removes v1 when migrating. No upgrade or migration command was
executed.

The OAR session checks above do not verify those UI or PTY changes. Upstream
service-tier support alone does not establish an ACP session option with
readback: OAR's existing `serviceTier` refusal is unchanged. This update
changes no adapter, dependency pin, public contract, assertion or timeout.

## Reproduction and artifacts

Set `OAR_OPENCODE_BIN` to the absolute path of the isolated 1.19.0 executable.
For the live commands, use empty home/config/data/state/cache directories,
remove provider credentials from the child environment, and disable automatic
updates and external plugins. The local-provider probes create their own
temporary configuration. None of today's probes used an account or repeated
a login flow.

```sh
node --import tsx experiments/runtime-versions.ts
CI=1 OAR_TEST=opencode-aimock pnpm exec vitest run sea-trial/vendor --no-file-parallelism
node --import tsx experiments/opencode-prompt-options.ts
node --import tsx experiments/opencode-release-lines.ts "$OAR_OPENCODE_BIN" /path/to/empty/project /path/to/results catalog control mcp abort dispose
node --import tsx experiments/live-contract.ts opencode --only basic,tool-detail,resume --out /path/to/live-results
CI=1 pnpm run check
pnpm run build
```

Local evidence remains in the xxwork Otter workspace under
`artifacts/opencode-1.19.0-*` and
`artifacts/runtime-versions-2026-10-11-*.json`. The live directory contains
the selected boundary report, complete native records and three voyage logs.
The initial inventory is retained separately from the two final inventories.

The complete local check passed, including 1,690 tests and the mock behavior
suite (18 passed, one account-usage skip). Both packages built successfully.
