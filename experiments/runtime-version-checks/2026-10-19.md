## Claude 2.1.303

The [official changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#21303)
describes general bug fixes and reliability improvements without naming an
interface change. The existing native vendor suite passed all 48 applicable
tests, covering MCP attachment and resume, catalog changes, tool denial,
streamed tool input, child attribution, structured output, model settings,
additional directories, error redaction and session naming. The shared
behavior suite passed 17 cases; account usage and catalog-dependent effort
enumeration skipped on this scripted backend. These checks establish the
tested integration boundaries, not real-account provider behavior.

The direct MCP name probe again found the ordinary `plainname` server
connected and its `mcp__plainname__ping` tool in the provider request. Each
of `__proto__`, `__defineGetter__`, `__defineSetter__`, `__lookupGetter__`
and `__lookupSetter__` was absent from both the native initialization's
server list and the provider's tool list. All six turns ended successfully,
including those with the silently omitted server. OAR's existing refusal
of these names remains necessary. The catalog vendor test also continues
to support `mcpToolsListChanged: "additions"`.

## Reproduction

After installing dependencies, select the isolated 2.1.303 executable with
`OAR_CLAUDE_BIN`. Give the child processes a disposable HOME/configuration
and clear inherited Anthropic credentials. The vendor and behavior helpers
provide their own local provider and dummy key:

```sh
OAR_TEST=claude-aimock CI=1 node node_modules/vitest/vitest.mjs run sea-trial/vendor --maxWorkers=2
OAR_TEST=claude-aimock node --import tsx sea-trial/main.ts
node --import tsx experiments/claude-reserved-mcp-names.ts
```

Invoke installed tools directly when changing HOME: invoking pnpm there can
select a different package store and trigger dependency reinstallation.
The first inventory/name-probe launch encountered that package-manager
setup check before running the probe; direct launches completed normally.
No assertion, test timeout or runtime behavior was changed.
