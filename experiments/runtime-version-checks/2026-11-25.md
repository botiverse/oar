# Runtime version check: 2026-11-25

Antigravity 1.5.17 passed 18 shared behavior cases and 21 vendor tests on
Linux. Google published it 50 minutes after the scheduled candidate freeze.
That run passed all 39 jobs, including three-platform checks for Cursor SDK
1.5.0 skill discovery and the OpenCode 2.4.1 skill-discovery refusal.
The [selected evidence](2026-11-25.json) records the frozen versions,
original CI failures, available retries and four official updater manifests.

## Antigravity

The freeze at 06:33 UTC recorded the accepted 1.5.16 and selected zero
Antigravity jobs. Google published 1.5.17 at 07:23 UTC. At the follow-up
check, the Linux x64, macOS arm64 and x64, and Windows x64 manifests all
specified 1.5.17. The baseline stays at 1.5.16 pending a scheduled
1.5.17 pass on Linux, macOS and Windows.
[Release](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.17),
[frozen candidates](https://github.com/botiverse/oar/actions/runs/45561456524/artifacts/14998625599).

The release changes when background shell commands notify the agent, how
OAuth tokens refresh during long turns, and how streaming resumes after
temporary model-capacity errors. It also changes quota countdown formatting
and remote MCP OAuth refresh. OAR's Linux ACP checks exercised scripted
turns, steering and resume, including working directories with spaces,
Unicode and literal percent signs. The local tests used a simulated
provider. Enterprise authentication, live quota and hour-long token refresh
remain unmeasured.
[Resume fix](https://github.com/botiverse/oar/pull/1179),
[usage label fix](https://github.com/botiverse/oar/pull/1193).

### Kimi initial MCP tools

Kimi 2.8.0 exposed the initial tool on both turns when the MCP server
delayed discovery by one second. The prepared-server control also exposed
it on both turns. A second run of both fixtures returned the same result.

tests still expects the cold-start omission on every version from 2.6.0.
