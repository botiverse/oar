## Antigravity 1.4.1

The [ACP registry](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json)
points to the [official 1.4.1 distribution](https://dl.google.com/agy-extensions/releases/linux/agy-acp-server-1.4.1-linux-x86_64.zip).
The native installation probe reports 1.4.1. Local comparison of the
distributed ACP Python source with 1.4.0 found model-selection and gateway
changes: Agent Platform's default changes to Gemini 4 Argon, disabled OAuth
models are filtered, effort variants extend beyond Gemini families, and
gateway header precedence is normalized case-insensitively. These are
source observations only. OAuth, Vertex, enterprise gateways, and their
account-specific catalogs were not exercised. The API-key configuration
used here retained its existing model/effort behavior.

Nine native tests passed: instruction and effort settings, MCP attachment
on new and resumed sessions, MCP name precedence, built-in tool denial
and its persisted filter, image-only input, missing login, unknown model
and invalid provider key. The invalid-key test pins the existing limitation:
the native prompt returns `end_turn`, so OAR reports completed. Passing
that test does not mean the provider failure has become classifiable.

The shared session experiment now accepts `antigravity`, using the same
cases and deadlines as the Grok/OpenCode path. Fifteen cases passed,
including multi-turn state, queue/withdraw, stream replay, resume, abort
and disposal. Four skipped: account usage, catalog-dependent effort
enumeration, and two steer cases (the native session has no steer).
The abort case uses delayed provider output; it does not establish that
native cancellation interrupts a running shell command.

The direct settings probe confirmed appended instructions on creation and
resume, low/high thinking in provider requests, and removal of the previous
append when omitted on another resume. Omitted effort again selected high.

### MCP persistence and file permissions

Harmless MCP env/header sentinels still appear in the native conversation
database and WAL after disposal. OAR therefore continues to refuse MCP
entries carrying those fields.

The first 1.4.1 probe produced `0644` files, unlike the earlier `0600`
observation. Controlled checks separate this from a version regression:

| Native version | Inherited umask | Database / WAL mode | Both sentinels retained |
| --- | --- | --- | --- |
| 1.4.1 | `0022` | `0644` / `0644` | Yes |
| 1.4.0 control | `0022` | `0644` / `0644` | Yes |
| 1.4.1 | `0077` | `0600` / `0600` | Yes |

The former `0600` observation is not a permission guarantee enforced by
the runtime. The native settings probe now reports the inherited umask and
home mode alongside each file mode, keeping environment restrictions
separate from runtime guarantees. All temporary data is removed at the end.

### MCP tool-list updates

The existing catalog probe warmed native discovery, called alpha, replaced
it with beta, called beta, and deliberately called removed alpha. After
the list-change notification, the client called `tools/list` again and its
`systemInstruction` catalog contained only beta. Beta executed. The final
alpha attempt reached `tools/call`, but no host handler ran for it. The
handlers saw exactly one alpha call before replacement and one beta afterward.
This agrees with the existing `mcpToolsListChanged: "full"` declaration.

## Validation and reproduction

`CI=1 pnpm run check` passed: typecheck, lint, 1,840 unit tests and the
mock behavior suite. The first check rejected the deprecated Node umask
getter; the probe now reads `/proc/self/status` on Linux without changing
process state, and its native recheck passed. No assertion or timeout was relaxed.

Install dependencies normally, then use a temporary HOME/XDG configuration
and set `OAR_ANTIGRAVITY_BIN` to the 1.4.1 server, with its matching
`localharness_external` beside it:

```sh
OAR_TEST=antigravity-aimock pnpm vitest run sea-trial/vendor --maxWorkers=2
pnpm tsx experiments/acp-aimock-behavior.ts antigravity
pnpm tsx experiments/antigravity-native-settings.ts
pnpm tsx experiments/mcp-tools-catalog-changed.ts antigravity
```

For the permissions comparison, run the settings probe in separate shells
with `umask 022` and `umask 077`; repeat the `022` case using the 1.4.0 pair.
Only the probe emits harmless sentinels through the native protocol to
measure persistence; OAR's public refusal is not bypassed in ordinary sessions.
