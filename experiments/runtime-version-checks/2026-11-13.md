The [focused native comparison](../opencode-child-background/README.md)
explains the missing edge. 2.3.0 makes subagents run in the background.
Without a client capability, the legacy standard child projection only
applies during the originating prompt. The native child completed and its
parent received a completion report, yet waiting 60 seconds after the parent
prompt returned produced no attributed child frame. With
`clientCapabilities._meta["opencode/child-session-updates"]: true`,
`opencode/session/child_update` delivered creation, running, child text and
completion. Text and completion arrived after the parent prompt returned.
The extension carries explicit root, parent and child session IDs; it does
not carry a parent tool-call ID. This needs adapter support, not merely a
longer wait in the existing test. The native extension comparison is not a
validation of a changed OAR adapter.

The OAR-free startup probe failed three of four simultaneous first starts
with exit 1 and `table account_state already exists`. Both serial starts
and all four concurrent starts after initialization became ready. The
separate ACP probe succeeded in both cold and both prepared opens. A
successful ACP sample does not clear the native cold-database race; neither
probe's zero process exit is a summary of every observed native outcome.
