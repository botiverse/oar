## OpenCode 2.0.27

The [native release](https://github.com/anomalyco/opencode/releases/tag/v2.0.27)
was checked using free `opencode/big-pickle`, empty home/config/data/state/cache
directories and a child environment excluding provider credentials. No
account, login flow or paid model quota was used.

### Model catalog

Two separate fresh configurations each ran `models --standalone`: exit 0,
empty stderr and the same 11 model IDs. OAR's existing `listModels()` path
returned `ok` with exactly those IDs in another fresh configuration. It
creates neither a session nor a persistent native service for this query.

The old boundary probe expected v2 to return `unsupported`, which pinned
the 2.0.26 cold-catalog failure. Its first 2.0.27 run therefore failed that
obsolete assertion. The probe now requires an `ok`, nonempty catalog and
passes its working directory to the query; the updated probe passed. This
changes the experiment's expectation, not the adapter. The empty-response
fallback remains intact, and
[upstream #53724](https://github.com/anomalyco/opencode/issues/53724) was
still open when checked. These successful cold queries do not establish
that every configuration in that issue is fixed.

The forced-concurrency probe deliberately bypasses OAR's absent v2 `steer`
member. In its first attempt, the native database held an assistant entry
with no content until disposal at the unchanged 180-second deadline; it
did not reach the concurrency precondition. The successful focused run is
separate evidence, not a reclassification of that timeout. Its cause was
not established.

The native additional-directories probe also passed without a model call:
new-session roots were visible in `session/list`; a cold resume omitting
the option cleared them; supplying a new root replaced them. The v1-only
prompt-configuration and provider harnesses were not run against v2, and
the separate HTTP-server interface was not re-probed.

### MCP resume failure

In the original run, the new session first saw no echo tool, then a native
catalog update added it after a resource-list call. It called the real
stdio echo server through `execute` and received the expected result.
The cold resume supplied the same server again, but its first turn ended
without calling any tool.

Read-only inspection of the native log and persisted messages established:

1. At 10:24:30.096 UTC, OpenCode logged `mcp connected` with one echo tool.
2. At 10:24:30.151, it saved a `core/codemode` instruction saying that
   `tools.echo.echo` had been removed and must not be called.
3. At 10:24:30.155, it saved the resumed user input. No restoring catalog
   update arrived before the turn finished.

A focused 2.0.26 comparison and a separate 2.0.27 comparison both called
echo on new and resumed sessions. ACP wire capture on the latter confirms
the same server was sent in both open requests. The relevant ACP
`sessions.ts`, `service.ts` and core `mcp/index.ts` files are identical
between those tags. This does not establish when the problem was introduced.

The independent
[`opencode-mcp-resume-native.ts`](../opencode-mcp-resume-native.ts)
reproduction uses Node built-ins, raw ACP JSON-RPC, its own stdio echo
server and a fresh native process for each turn. It imports no OAR code.
Its first six cold resumes reproduced the failure once; the other five
and the initial new session returned actual echo results. In that failure,
OpenCode logged echo connected at 10:40:02.945, then saved the removal
notice at 10:40:03.227. A subsequent resume restored the tool.

A second independent loop reproduced missing echo results on two of its
five completed resumes, again with native removal notices. Its sixth
resume timed out in `session/prompt` at the unchanged 180-second deadline;
that timeout is recorded separately, not counted as a completed catalog
failure. After polishing the standalone script, a final new/resume smoke
passed. These comparisons retain the intermittent failure rather than
replacing it with a passing run.

The exact-tool-result assertion is retained. OAR adds no sleep, fabricated
result or readiness claim. The native synchronization problem and the
upstream-report preparation are tracked in #371; a successful comparison
does not close it.

## Reproduction and evidence

The boundary checks require empty native directories and no inherited
provider credentials. The direct native reproduction creates that isolated
environment itself and retains it for diagnosis. Its result checks actual
completed tool updates, not the assistant's answer text; a missing echo
sets a nonzero exit status while allowing the remaining resumes to run.
It also saves ACP wire messages, native persisted messages and connection
timestamps. No upstream report was posted during this check.

```sh
node --import tsx experiments/runtime-versions.ts
node --import tsx experiments/opencode-release-lines.ts "$OAR_OPENCODE_BIN" /path/to/empty/project /path/to/results
node --import tsx experiments/acp-additional-directories-native.ts opencode "$OAR_OPENCODE_BIN"
node experiments/opencode-mcp-resume-native.ts "$OAR_OPENCODE_BIN" /path/to/native-results 6
CI=1 pnpm run check
pnpm run build
```
