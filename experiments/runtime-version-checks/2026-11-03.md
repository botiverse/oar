## Qoder 1.1.82

The same synthetic replay fixture was run against 1.1.81 and 1.1.82. Both
initialize the requested selector `efficient` as `Efficient`. In 1.1.81,
both cache and live catalogs include `serverModel.display_name: "Efficient"`,
and OAR opens the session. In 1.1.82, both omit `serverModel`; `displayName`
still says `Efficient`, but that UI label is not the native identity field
required by the existing contract. OAR refuses opening after its live read.
The new [catalog reproducer](../qoder-native/replay-catalog.ts) retains only
selected model fields and the public opening outcome.

All fifteen behavior failures and ten vendor failures occur at model
confirmation. The remaining vendor failure is independent: the permission
test launches the native transport directly, bypassing OAR's model check.
It passes on 1.1.81 with one permission request/reply. On 1.1.82 it returns
`error_during_execution`, error code 10500 and `Internal Server Error`, with
zero permission requests/replies and zero reported usage. Its existing success
assertion now includes the native result and permission counts on failure.

The 1.1.81 bundle has two calls to `getFakeResponseStore` besides its
declaration. The 1.1.82 bundle retains the declaration and CLI replay option,
but no calls under that method name. This is source evidence of a changed
replay path, not proof that a remote model service is unavailable or a complete
explanation of the native error. Account-backed model selection and inference
were not tested. Product confirmation, test assertions and deadlines remain
unchanged. The model identity and replay changes require separate investigation;
CI currently installs latest Qoder and will encounter these failures too.

## Cursor 1.3.0

The isolated SDK passed eleven local login scenarios and the network guard.
Four configuration controls preserved stored synthetic credentials: OAR's
default/exclude modes, including reopen, did not read user configuration or
connect its MCP server; the native positive control did both. Authenticated
requests reached the local mock backend, which intentionally ended them in an
error without inference. This proves configuration selection, not a successful
model turn.

The interrupted-run offline control still rejects `summarize()` with
`Agent <agent> already has active run`, both with and without an attempted
`local.force`. It neither starts an executor nor makes a network request, and
the saved active run is unchanged. The probe now reads the installed SDK's
version rather than printing a hardcoded 1.2.0.

The exported declaration diff adds `hostMcpBridgeUrls` to local executor
options and an internal log-redaction helper. That inspection and the local
controls do not establish 1.3.0 upgrade/resume, tool execution or compaction
compatibility against a real backend. No peer, dependency or CI pin changes
to Cursor are included.

## Qwen 0.26.6

All eighteen vendor tests and sixteen applicable behavior cases passed, with
three capability skips. The vendor battery includes the four duplicate tool-id
regressions and the existing prompt-resume/compaction controls. Direct native
controls covered fresh and resumed plain replies, separate thinking/text blocks,
MCP execution, default permission handling and a configured model catalog.
MCP controls verified distinct fresh/resumed echo results, not just tool-call
frames. Default permission mode asked once in each process; yolo asked zero
times. Interrupt ended its turn with a native error result; a subsequent input
completed in both fresh and resumed processes.

The reply structure still has one `message_start`, two block starts at index
zero and separate thinking/text snapshots; the text snapshot's id differs from
the initial message id. OAR keeps its structural association workaround.

Holding the extension-store lock in a previously warmed home still allows
initialize to return (1,738 ms here), while the first prompt reaches no provider
until the lock is released. An ordinary later prompt completes even while the
external lock is held again. This is not a guarantee for every later extension
operation. The 0.26.6 OAuth refresh-lock change does not establish a fix for this
different extension-store boundary.

The published bundle's fourteen provider-preset key names and four native auth
key names are all covered by OAR's existing credential reader. No new credential
key or structural fix was found in this check. These controls do not rerun the
separate automatic/manual compaction-attribution experiment.

## Repeating the checks

Install each named npm version into a separate prefix, then point
`OAR_CLAUDE_BIN`, `OAR_QWEN_BIN`, `OAR_CODEBUDDY_BIN` and `OAR_QODER_BIN` at
the corresponding absolute executables. Run the behavior and vendor suites
with the matching backend, for example:

```sh
OAR_TEST_REQUIRE_AVAILABLE=1 pnpm tsx sea-trial/all.ts qoder-native
OAR_TEST=qoder-native pnpm vitest run sea-trial/vendor --maxWorkers 2
pnpm tsx experiments/qoder-native/replay-catalog.ts /absolute/qodercli 1.1.82
```

The Qoder commands above reproduce known failures. Compare 1.1.81 only as a
diagnostic control. For the remaining probes, use
[Qwen's protocol probe](../qwen-native/probe.ts) and
[lock probe](../qwen-native/lock-lifetime.ts),
[Claude's login probe](../claude-login-browser/probe.ts),
[Cursor's offline summarize probe](../cursor-summarize-force-offline.ts), and
the unchanged CodeBuddy
[stream-json](../codebuddy-native/2026-10-29/codebuddy-consecutive-prompts.mjs)
and [ACP](../codebuddy-native/2026-10-29/codebuddy-acp-consecutive-prompts.mjs)
reproducers with its verified standalone executable. Cursor's probes load the
SDK installed in the worktree; restore the required 1.2.0 before repository checks.
