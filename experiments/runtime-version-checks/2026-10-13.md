## Pi 1.2.0

The [native release](https://github.com/earendil-works/pi/releases/tag/v1.2.0)
changes extension startup semantics: `before_agent_start` also runs for
custom messages that trigger turns. Its event is discriminated by
`messageType`; custom messages have `message`, while user messages have
`prompt` and `images`. The session is busy during starting hooks, and an
abort received there is deferred until the run starts. OAR keeps the
extension API native and does not emulate the old event shape.

The real SDK with a local scripted provider passed 38 vendor tests and all
applicable shared behavior cases. This includes extension lifecycle,
native abort, MCP, tool denial, provider errors and resume. A separate
process opened a session with Pi 1.1.0, then Pi 1.2.0 resumed it: session id,
model and prior transcript survived, and the new OAR record stream began
at seq 0. Both checkouts had identical Pi adapter files, isolating the SDK
upgrade in that probe.

The dependency floor is now `^1.2.0`, with exact 1.2.0 development pins.
No login-provider flow was repeated. The checks do not validate every
third-party extension or provider introduced by the native release.

## Pi Durable and Chord 1.2.0

The host must upgrade both optional peers to the 1.2 line:
`@earendil-works/pi-durable@~1.2.0` and `@earendil-works/chord@~1.2.0`.
The companion packages are tested at exactly 1.2.0. Chord's context subpath,
used by OAR, remains available; its unrelated root facet APIs changed in
this release.

The [native Durable changelog](https://github.com/earendil-works/pi/blob/v1.2.0/packages/durable/CHANGELOG.md)
requires these adjustments:

- Tool implementations return model content in `ToolExecutionResult.output`,
  replacing `content`. `structuredOutput` is a separate native tool channel.
  Transcript tool-result messages still carry `content`, which OAR reads.
  The existing tool regression now returns `output` and still requires the
  explicit final result to replace progress text.
- Storage failures close the native session and its watch with
  `session_failed`. OAR records a JSON-safe error summary, records `exited`,
  and refuses subsequent controls with `runtime_exited`. A real
  `MemoryStorage.commit` failure verifies this path; JSON persistence also
  retains the message when the original error has a cyclic cause.
- Native nested tool calls now carry a result summary instead of a model
  transcript entry. OAR uses its actual `isError` flag for ok/failed and
  does not invent result content. Running nested calls are adopted from
  `snapshot.nestedTools`. Success, failure and a second controller attaching
  mid-call are checked against the real Harness. Native parent/task ids and
  structured tool output remain in the raw batch.

All 22 Durable vendor tests and applicable shared behavior cases passed.
The native JSONL probe still preserves instructions and request-id
deduplication across close/open. This is same-version storage recovery;
cross-version recovery of an unfinished Durable tool task was not tested.
The browser demo passed in Chromium with its native fetch provider routed
to local HTTP responses: rendering, abort, request states, disposal and
credential cleanup. No new OAR event shape is introduced. Compaction end
receipts, including 1.2.0's error text, remain raw in this adapter.

## Grok 1.0.52

A raw ACP probe with an isolated Grok home captured the actual provider
request, without depending on model obedience. New findings:

| Native options | Provider system message |
| --- | --- |
| New replacement and append | Replacement, then append inside native `<human_rules>` |
| Resume with both changed | Both new values, with the same native wrapper |
| Resume with neither | Saved instructions unchanged |
| Resume with replacement only | Saved instructions replaced |
| New append only | Native instructions retained, followed by rules |
| Resume with append only | New rules ignored; saved instructions unchanged |
| Empty/whitespace replacement, with or without append | New sessions retain native instructions; resumed sessions retain saved instructions |

OAR now passes `_meta.systemPromptOverride` and `_meta.rules` independently.
The old adapter concatenation, needed for 1.0.46 and 1.0.50, is removed.
**Host-visible change:** when both options are supplied, Grok now formats
the appended instructions in its own `<human_rules>` section. Append-only
resume remains refused before launch. Empty or whitespace-only replacement
is now also refused as `systemPrompt`: native Grok treats it as omitted,
which cannot fulfill a replacement request. No older-version compatibility
branch was added. The runtime page and matrix carry this boundary.

The first run of the old native probe failed its obsolete assertion that
an override suppresses rules. Its failure is retained separately from the
updated passing probe. An additional empty-replacement capture found the
silent fallback above; the permanent native probe and pre-launch refusal
tests now cover empty/whitespace values on creation and resume, with and
without an append. The new vendor regression checks exact provider
instructions on successful new and resumed turns. It excludes Grok's
separate dashboard-summary request, which has no agent tools or session
instructions. Native control, MCP, error and structured-output regressions
also passed against the local provider.

The background-usage probe also passed all three completion orders: totals
were 2810/31 for foreground, 2820/32 for child-first background, and 2120/25
for parent-first background. The last still omits the late child's 700/7,
as [previously documented](../grok-background-usage-2026-10-10.md). The native
zero reasoning count is preserved. The old probe first failed because its
expected object omitted that field added by OAR's reasoning support; its
updated assertion requires the explicit zero and the same totals.

The 1.0.52 `agent --help` still exposes no tool-denylist argument. The public
source snapshot remains `2bdd1d6a`, older than this binary; it is not evidence
of the new prompt behavior. OAR's existing disallowed-tools refusal remains.

## OpenCode v2 2.0.28

The [tag comparison](https://github.com/anomalyco/opencode/compare/v2.0.27...v2.0.28)
contains no ACP/MCP file change. With fresh home/config/data/state/cache
and no inherited provider credentials, the boundary probe passed:

- Cold `listModels` returned `ok` with 12 ids.
- Both prompt options were refused. Concurrent input used the queue, then
  completed two turns. A forced raw concurrent prompt received the native
  refusal and `input_dropped: runtime_refused`; the original turn completed.
- Child attribution produced seven child frames and one graph edge, and the
  child shell result reached the root answer.
- Resume kept the session id and recalled the marker. The MCP echo tool ran
  on both new and cold-resumed sessions in this run.
- Abort and dispose during a shell call each ended the turn as aborted.

A passing MCP resume does **not** resolve the intermittent catalog race in
[OAR #371](https://github.com/botiverse/oar/issues/371). In
[upstream #54794](https://github.com/anomalyco/opencode/issues/54794#issuecomment-6123225428),
an independent reproduction observed the tool-removal notice on all 12 cold
resumes; actual tool failures depend on when the model sees the later
catalog update. A contributor is
[working on synchronous refresh](https://github.com/anomalyco/opencode/issues/54794#issuecomment-6132422908).
The issue remains open, with no published fix to validate. No retry, sleep or
weakened echo assertion was added to OAR.
