# Runtime version check: 2026-11-20

The November 20 candidate run passed 41 of 42 jobs. Its one failure was
a macOS Claude fixture using two spellings of the same directory. A separate
Linux check found a login difference on Claude 2.1.330: the local OAuth
control timed out twice before delivering a sign-in URL. Claude 2.1.326
completed the same control. [Candidate run](https://github.com/botiverse/oar/actions/runs/44688370385),
[macOS fixture fix](https://github.com/botiverse/oar/pull/1067).

The release window runs from November 19 at 21:09:10.722 UTC, exclusive,
through November 20 at 21:07:59 UTC. The scheduled workflow froze its
candidates at 06:31 UTC on November 20. The additional Linux controls ran
on **November 21**, on OAR `6674fe6d`, using isolated homes, scripted
providers and zero real-account submissions. The evidence includes the
15 release sources, registry publication times, exact tested versions and
one entry for each of the 106 failed CI jobs. [Selected evidence](2026-11-20.json).

## Claude login

On 2.1.330 the synthetic browser opener ran once in each default-mode
attempt. OAR delivered zero URLs, the loopback server saw zero exchanges,
and login returned `timed_out` after 30 s. On the pinned 2.1.326 the
default, suppressed and failing-opener cases each delivered one URL,
exchanged a code and verified the profile. This isolates the difference
to the version in this Linux fixture. The point at which the new version
stops delivering the URL remains unverified. [Local OAuth control](../claude-login-browser/probe.ts).
