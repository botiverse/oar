A separate [Windows check](https://github.com/botiverse/oar/actions/runs/41457627797/job/125318274040)
failed the Kimi login confirmation-abort fixture after the expected
`logged_in` result: an immediate `kill(pid, 0)` did not throw. The fixture's
Windows command wrapper creates a descendant, while OAR's exit contract
finishes after descendant stopping actions and does not promise instantaneous
OS reaping. The log lacked the failing PID and creation-time identity, so it
cannot uniquely attribute this failure to delayed reaping or exclude PID
reuse. An approved test-only follow-up will bound the disappearance wait,
check creation identity and distinguish those outcomes. Product cleanup is
unchanged. The release owner's single-job rerun passed.

The release commit also had an automatic push
[CI run 41456702500](https://github.com/botiverse/oar/actions/runs/41456702500):
created at 13:52 UTC and successful at 14:44 UTC. It is distinct from the
manual run that encountered the Kimi fixture failure. An initially empty
head-filtered API listing had been mistaken for a missing trigger; the
recorded push run corrects that conclusion. A temporary empty list is not
proof that CI was not triggered.
