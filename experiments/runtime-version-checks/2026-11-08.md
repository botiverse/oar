permissions, effort, tools, resume and background task notifications.

Five direct protocol scenarios and the held-lock control are recorded in
the selected JSON. Fresh and resumed thinking/text replies each still emit

expected text and thinking exactly once in the vendor regression. The
published source still finalizes a snapshot and assigns a new id when its
block type changes; these are current native observations, not an assumption

on resume, and require actual echo results from both native processes.

use yolo. Interrupt and follow-up results remain separately recorded.

With the extension-store lock held, a process using a warmed HOME returns
initialize in 1,754 ms. Its first prompt sends no provider request during
the 300 ms observation, then completes after the lock is released. An
ordinary later prompt completes with the lock held again. Initialize is
still not an extension-readiness barrier; the later control does not cover
every extension operation.

Provider-name comparison finds fourteen preset credential variables and four
native authentication keys, all already covered by OAR's local reader.
This compares names in the published bundle; it reads no credentials and

### Pending stream-identity fix

[PR #16586](https://github.com/QwenLM/qwen-code/pull/16586), linked from
[issue #15875](https://github.com/QwenLM/qwen-code/issues/15875#issuecomment-6716941032),
remains open and unmerged at `13af4a0f`. The contributor proposes one message
id per response and continuous thinking/text block numbering. The
[upstream review bot](https://github.com/QwenLM/qwen-code/pull/16586#issuecomment-6722241500)
flags local `tool_use` numbering that could collide under that shared id.
This is a static review of an unmerged change, not an observed defect in a
released Qwen version.

Once a stable version contains the final fix, rerun behavior, vendor tests
and the snapshot replay with both **thinking -> text -> tool_use** and
**text -> tool_use**. Compare native message id, block index/type and tool
call id across deltas and snapshots, then verify that OAR loses or duplicates
neither text/thinking nor tool events and keeps tool arguments associated
with the right call. Only then document the first verified stable version
with consistent ids. Keep positional/type snapshot compatibility for older
versions. The daily runner's comment now records this rule instead of its
older suggestion to remove the compatibility handling.
