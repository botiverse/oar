## Pi 1.4.0

OAR's Pi Coding Agent and Pi AI dependencies now require `^1.4.0`. Root
development dependencies pin 1.4.0; the lockfile and the nine Earendil
release-age exceptions follow the same release. No adapter code changed.

The [native release](https://github.com/earendil-works/pi/releases/tag/v1.4.0)
includes resumed extension-tool activation fixes, summary output-limit
changes and provider/model catalog updates. Today's native suite includes
tool selection on fresh and resumed sessions, restored pending tools,
extension lifecycle, inventory, MCP list changes and native controls. All
63 applicable tests passed on the first run, as did all 17 applicable
shared behavior cases.

The existing separate-process upgrade probe created a session with 1.3.0,
then opened it with 1.4.0. Native identity and saved model stayed the same;
the resumed provider request contained the old user message, old assistant
answer and new input. The new OAR record stream began at sequence zero.
This checks conversation continuity, not recovery of unfinished execution.
The native release's other provider and compaction fixes were not separately
exercised with real services.

## Pi Durable and Chord 1.4.0

Both optional host peers move from `~1.3.0` to `~1.4.0`; development and
test dependencies pin 1.4.0. A Durable host must upgrade both peers together.
OAR's existing adapter, native fixtures and browser demo compiled without
source changes against the new interfaces.

All 23 native tests and 18 applicable shared behavior cases passed on the
first run. The native probe again observed terminal submission receipts
after `run_end` within the same batch, preserved instructions across JSONL
close/open, and deduplicated the earlier request id after reopening. The
Chromium demo passed native fetch-provider conversation rendering, request
states, abort, cleanup and no stored key using MemoryStorage and a local
scripted Anthropic endpoint.

The native [Durable changelog](https://github.com/earendil-works/pi/blob/v1.4.0/packages/durable/CHANGELOG.md)
documents an automatic SQLite schema-2 migration on open. A migrated
database cannot be reopened with 1.3.0 or earlier. JSONL requires no schema
migration, but older versions do not resume the new sleeping tasks. Native
extension authors also need to replace `TaskRuntime.sleep()`, handle the
new sleeping state, supply document `checkpointWhen` predicates and update
hand-built runtime/tool objects. The new crash-loop guard parks repeatedly
interrupted tasks after its configured restart limit. Custom
[Chord contexts](https://github.com/earendil-works/pi/blob/v1.4.0/packages/chord/CHANGELOG.md)
now require a telemetry span. These are upstream migration requirements;
today's OAR checks do not validate SQLite migration, sleeping-task recovery,
crash-loop recovery or arbitrary host extensions.

## Claude 2.1.308

The [native changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#21308)
lists maintenance fixes, with the intervening 2.1.307 entry covering MCP
retry/catalog behavior and browser-login completion. All 51 native tests
and 17 applicable shared behavior cases passed on the first run. Default
startup traffic remained enabled. The reserved-name probe still dropped
all five refused MCP names while exposing the ordinary control tool.
ToolSearch removal checks still exclude removed tools from discovery, keep
previously loaded schemas in the conversation, and reject their execution.

The Linux login-browser probe passed all three modes with synthetic local
OAuth: default browser once, `openBrowser: false` zero times, and a failing
opener once without a default-browser fallback. Each emitted one URL and
one code prompt, verified the exchange, and returned `logged_in` from login
and subsequent status. Windows and macOS were not rechecked for this
version; their earlier evidence and macOS completion limitation remain.

## Grok 1.0.67

The resolved binary identified `1.0.67 (2fe064390d07)`. All 15 applicable
native tests and 17 applicable shared behavior cases passed on the first
run. The native prompt-options probe still shows independent replacement
and append channels on creation and resume, and preserved saved
instructions. Blank replacements and append-only resume remain ignored
natively; OAR continues to refuse them. No refusal was removed on the basis
of the version change.

The fixtures used dummy keys and local Chat Completions providers. Grok
also attempted native Responses requests for `grok-4.6`; those were rejected
for the dummy key. These additional captured errors do not establish a
successful live-model check. No existing account or model quota was used.
