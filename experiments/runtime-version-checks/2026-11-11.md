# Runtime version check: 2026-11-11

## Scope

This early check covers Cursor SDK 1.3.1, following the October 28 live
procedure. The ordinary daily runtime inventory is separate and has not
been run for this report. Base: `2083f1ee`; Linux x64, Node 24.19.0,
`gpt-5.4-nano`. The installed package was confirmed as 1.3.1 before and
after the probes. The SDK read an existing stored login; `CURSOR_API_KEY`
was absent and no new login was performed.

[Selected results](2026-11-11.json) retain case outcomes, native summary
states, timings and reported token usage. They omit account identities,
agent/run/request identifiers, local transcript paths and credentials.

## Cursor 1.3.1

All twelve applicable cases in the unchanged
[`live-contract.ts` battery](../live-contract.ts) pass on the first run:

| Case | Observed result |
| --- | --- |
| basic | Exact requested text, native evidence on every event, nonzero usage |
| multi-turn | Three prompts, one turn end each, cumulative usage retained |
| tool-detail | Shell input and output marker present, matching call ids |
| busy-and-late-control | Overlapping prompt rejected busy; idle abort/steer rejected no_active_turn |
| steer | Native complete_delivered acknowledgement; new text lands in the same turn |
| queue | Accepted nondurable queue starts its own turn without another prompt request |
| abort | Accepted before turn end; outcome aborted |
| dispose-mid-turn | Outcome aborted; later prompt rejected disposed |
| cursor | Contiguous record sequence and complete replay match |
| resume | Same agent id, recalled marker and retained model selection |
| subagent | Child updates attributed by agentPath; no invented child session or graph edge |
| bad-model | Unknown model rejected at open |

`kill-runtime` is skipped because the SDK runs in process and has no
separate runtime process to terminate. No case was retried or weakened.
The shell case logs that tree-sitter natives are unavailable and command
analysis degrades to `parsingFailed`; shell execution and the tool-detail
assertions still pass. This does not establish native parser availability.

The [native compaction probe](../cursor-compaction.ts) also passes without
a retry. The ordinary text turn returns `STORED` through both `onDelta`
and `run.stream()`, with identical text. A manual summary emits
`running -> completed` and finishes. Cancelling the next summary at its
first `running` message returns `cancelled`, with no terminal summary
message. Each iterator ends in the same millisecond as `run.wait()`;
the clock resolution is one millisecond, so these zero gaps are not a
general timing guarantee.

This probe calls native `Agent.summarize()` directly. It does not fill the
context to trigger automatic compaction, repeat the separate live OAR
`session.compact()` control, or test resume across SDK versions. OAR's
compaction projection and control tests are included in the local suite.
The November 4 login/configuration and interrupted-run controls remain
[separate local/offline evidence](2026-11-04.md#cursor-131).

### Reported usage

Fourteen of eighteen native run results contain usage. Counting each
result once gives 197,374 input tokens and 1,833 output tokens, 199,207
total. The reported cache reads are 137,728 and cache writes zero;
reported reasoning tokens are 1,048. Cache and reasoning fields are not
added to input/output totals again. Stream usage and OAR's cumulative
usage are not added a second time.

The live abort and disposal runs, the completed native summary and the
cancelled native summary have no usage field. Missing usage is not zero:
the sum above is incomplete and is not an account bill or a price estimate.
No account usage endpoint was queried.

### Dependency decision and limits

Select exact SDK 1.3.1 for OAR's optional peer and development dependency,
the workspace development dependency and the CLI's direct dependency.
The lockfile and the existing pnpm release-age exceptions follow that
selection. The SDK remains host-owned for OAR consumers; Cursor stays out
of `defaultRuntimes`. Current installation instructions and unsupported
SDK diagnostics name the selected version.

No session adapter behavior, assertion, retry count or deadline changes.
Historical evidence continues to name the version actually tested. These
live observations cover this Linux account/model combination only; they
do not establish live macOS or Windows behavior, a fresh login/logout
flow, all models, or support for an SDK version range.

## Repeating the checks

The two live commands below use the existing Cursor login and consume
quota. Use new private output directories and the exact SDK version; do
not publish raw native summaries because they contain local transcript
paths.

```sh
pnpm install --frozen-lockfile
node -p 'JSON.parse(require("node:fs").readFileSync("node_modules/@cursor/sdk/package.json", "utf8")).version'
OAR_TEST_MODEL=gpt-5.4-nano pnpm tsx experiments/cursor-compaction.ts /tmp/cursor-131-compaction
pnpm tsx experiments/live-contract.ts cursor --model gpt-5.4-nano --out /tmp/cursor-131-live
CI=1 pnpm vitest run tests/cursor tests/login/cursor-auth-status.test.ts tests/login/cursor-environment.test.ts tests/login/cursor-login.test.ts tests/login/cursor-logout.test.ts
CI=1 pnpm run check
pnpm run build
CI=1 pnpm run clean-install
```

The live report's `version: bundled` describes installation discovery,
not the package version. Read the installed manifest as above. The
selected JSON lists each `cursor/run_result` once without its ids, then
adds the three native compaction run results; this is the basis for its
usage subtotal. The bad-model case fails before creating a session, so
there is no voyage file or run usage for it.
