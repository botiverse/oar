## Pi: use the native cancellation result

[Pi 1.1.0](https://github.com/earendil-works/pi/releases/tag/v1.1.0)
adds `aborted: boolean` to `agent_settled`. The installed
`dist/core/agent-session.js` (upstream commit
`abe508e1b89912adde45528136c3221eb69acdd7`) sets that flag through
`AgentSession.abort()`. That public method cancels retry, compaction and
branch-summary work, signals the agent, then waits for idle.

Two failures were reproduced before the adapter fix:

- OAR called only `abortRetry()` and `agent.abort()`. A host abort stopped
  the tool, but the SDK's settlement still said `aborted: false` because
  OAR bypassed the session's cancellation bookkeeping.
- The projection inferred cancellation from OAR's request state. An
  extension calling `ctx.abort()` without a host request therefore ended
  as `completed` instead of `aborted`.

OAR now calls the complete public cancellation method without awaiting its
idle wait. The control response is still accepted before the native turn
end. An abort taken over before `agent_start` is delivered when the SDK
creates the run. The projection reads the native `agent_settled.aborted`
flag: true means aborted; false retains the provider failure or normal
completion. An SDK abort-promise rejection is retained in a
`pi/abort_rejected` frame without inventing a turn boundary. Dispose still
awaits the SDK's idle before shutting down extensions.

The new native field is required, so both `pi-ai` and `pi-coding-agent`
dependency floors are now `^1.1.0`; OAR no longer advertises a range that
could install 1.0.x with this adapter. Workspace lock entries and the
release-age exemptions select 1.1.0.

All **30 applicable Pi vendor tests** passed against the real SDK and a
local scripted model provider, including a real extension that cancels a
tool call, host abort ordering, MCP, lifecycle/shutdown, images, tool
filtering, failures, effort and compaction. This includes PR #245's new denied-tool execution and resume regression. The serial behavior suite
passed all 17 applicable cases; its two capability skips were unchanged.
The early-abort unit regression and projection regressions passed too.
No account or paid model was used. These checks do not verify the release's
provider-specific model catalog, Azure, authentication or production MCP
OAuth changes.

The [cross-process resume probe](../pi-upgrade-resume.ts) created a session
with SDK 1.0.4 in the previous adapter checkout, then resumed it with SDK
1.1.0 and the updated adapter. The native id and saved model were unchanged,
the provider received the prior user and assistant messages, and the new
record stream began at sequence zero. This measures the complete adapter
and SDK upgrade, not the SDK as an isolated variable. It does not restore
unfinished execution.

## Cursor: precise dependency and evidence scope

Hosts using Cursor must install **`@cursor/sdk@1.0.37`** with this OAR
upgrade. Keeping 1.0.36 conflicts with the new exact optional peer. The OAR
CLI brings its own 1.0.37 dependency. Session interfaces are unchanged.

Comparing the installed declarations with 1.0.36 found new generated
`computerUse` tool shapes, but no incompatible public session, model or
auth interface change. This comparison does not verify computer-use
execution. The native
[login/logout probe](../cursor-login/README.md) passed its network guard
and **11/11 scenarios** using temporary homes and a local substitute
backend: success, cancellation/deadlines during polling and key minting,
previous credentials preserved after cancellation, and local-only logout.
Other outbound connections were rejected by the probe.

Adapter and login unit regressions are included in the full check. No
real-account session, model-listing request or native
`cursor-disallowed-tools.ts` probe was run for 1.0.37. The last full live
session result remains the 1.0.36 evidence in the
[October 6 report](2026-10-06.md); this upgrade does not relabel it as a
1.0.37 result.

## Reproduction

```sh
pnpm tsx experiments/runtime-versions.ts
pnpm tsx experiments/cursor-login/probe.ts
CI=1 OAR_TEST=pi-aimock pnpm vitest run sea-trial/vendor --no-file-parallelism
OAR_TEST=pi-aimock pnpm sea-trial
pnpm tsx experiments/pi-upgrade-resume.ts /path/to/previous-oar-checkout
CI=1 pnpm run check
pnpm run build
pnpm run clean-install
```

The behavior cases ran serially on xxwork to avoid competing native
processes. Version inventory used isolated `OAR_ANTIGRAVITY_BIN`,
`OAR_CLAUDE_BIN`, `OAR_CODEX_BIN` and `OAR_OPENCODE_BIN` overrides;
no managed executable was replaced. The first inventory omitted the
Antigravity override and reported it absent; the corrected inventory found
1.3.0. Pi and Cursor versions were resolved from their actual importers.

Raw before/after regression logs, inventory, login and resume results are
retained under xxwork's Otter workspace `artifacts/`, with names
`pi-1.1.0-*`, `pi-upgrade-1.0.4-to-1.1.0`,
`cursor-1.0.37-login.log` and `runtime-versions-2026-10-08*.json`.
