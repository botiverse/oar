## Native regressions and live checks

The vendor suites used the real new binaries with local scripted providers
and temporary homes. Claude's 40 applicable tests and Codex's 35 passed,
including MCP, tool denial, images, service tier, effort, interruption and
resume. The shared behavior suites passed their 17 and 16 applicable cases
respectively, with two and three unchanged skips. Their printed 19-case
totals include those skips. No runtime adapter, assertion or timeout changed.

The `basic`, `tool-detail` and `resume` live scenarios passed for both
runtimes. Claude reported `claude-haiku-5-5` for the requested `haiku`
alias; Codex used `gpt-6-luna`. Both retained tool identity and output, and
resumed sessions recalled the saved marker with the same session identity
and model.

Claude's streamed `tool_call_started` intentionally has no input. Its
later `tool_call_input` contains the full shell command and marker, as
confirmed in the retained voyage; the probe's `inputHasCommand: false`
fact describes only the earlier start event. Resume opens with no records
or model report, then reports its model on the first turn, matching the
current private-initialize contract.

The [Codex patch notes](https://github.com/openai/codex/releases/tag/rust-v0.162.1)
describe fixes to multiline TUI questions and background-server feature
compatibility at startup. The
[Claude changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
includes headless hook/MCP, workflow and resume fixes. The OAR checks above
exercise existing adapter behavior; they do not verify every upstream fix,
interactive UI behavior or other operating systems.

## Inventory coverage

`runtime-versions.ts` now includes Pi Durable without opening a Harness or
starting host-owned work. It resolves the installed SDK from
`sea-trial/harness/pi-durable.ts` and reports `installation: "host_supplied"`.
A matching package version alone says nothing about a host's configured
storage, model provider or execution environment.

OpenCode has two independent npm sources: `opencode-ai` for v1 and
`@opencode/cli` for v2. Each inventory row identifies its release line and
compares only a selected executable of that major version. The other row
reports `other_release_line`, preserving the observed installed version
without calling it outdated. Parsing also accepts v2's native
`opencode v2.0.26` output. Running the inventory with each real executable
confirmed the matching row was `current` and the other row was
`other_release_line`. All nine core runtimes were covered; no community
runtime was queried.

## Reproduction and artifacts

Select the exact binaries with absolute `OAR_CLAUDE_BIN`, `OAR_CODEX_BIN`,
`OAR_OPENCODE_BIN` and `OAR_ANTIGRAVITY_BIN` paths as needed:

```sh
node --import tsx experiments/runtime-versions.ts
CI=1 OAR_TEST=claude-aimock pnpm exec vitest run sea-trial/vendor --no-file-parallelism
CI=1 OAR_TEST=codex-aimock pnpm exec vitest run sea-trial/vendor --no-file-parallelism
OAR_TEST=claude-aimock pnpm sea-trial
OAR_TEST=codex-aimock pnpm sea-trial
# Requires an authorized existing login.
pnpm tsx experiments/live-contract.ts claude --only basic,tool-detail,resume
pnpm tsx experiments/live-contract.ts codex --only basic,tool-detail,resume
CI=1 pnpm run check
```

`artifacts/claude-2.1.296-*`, `artifacts/codex-0.162.1-*`,

`artifacts/runtime-2026-10-10-usage.json`. The initial inventory is retained
separately; pnpm printed installation chatter ahead of its JSON, so the
