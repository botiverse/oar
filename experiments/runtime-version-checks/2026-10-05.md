## Pi upgrade and compatibility

The [upstream changelog](https://github.com/earendil-works/pi/blob/v1.0.3/packages/coding-agent/CHANGELOG.md)
adds Azure Foundry Chat Completions, saves codemode images to files, and
fixes interrupted OAuth refreshes and some update/terminal failures.
The workspace pins and lockfile now select 1.0.3. OAR's existing Pi SDK
and provider dependency ranges remain `^1.0.2`, which already permit
1.0.3 on a fresh resolution. No adapter or OAR API changes are needed.

**Azure users must migrate the provider name.** Pi renamed
`azure-openai-responses` to `azure`. Update the provider keys in native
`auth.json`, `models.json` and applicable `settings.json` entries, and change
OAR model selections from `azure-openai-responses/<model>` to
`azure/<model>`. The `AZURE_OPENAI_*` environment variables retain their
names. Upstream also warns that the old prompt cache is not reused; this
check does not measure Azure caching or authentication.

## Old Azure sessions

**When resuming an old Azure session, explicitly pass
`model: "azure/<model>"`.** Without it, Pi can switch to an available
default model while retaining the session id and transcript.

[`pi-azure-upgrade-resume.ts`](../pi-azure-upgrade-resume.ts) verifies this
through OAR's real session path in separate processes. The 1.0.2 SDK's
`SessionManager` writes a synthetic conversation naming its builtin
`azure-openai-responses/gpt-4.1`. Each case starts from the same saved file
with SDK 1.0.3, a configured local fallback provider and unchanged OAR
adapter source:

| Resume request | Observed result |
| --- | --- |
| No `model` | Opens with the original id but selects the configured `aimock/aimock-model` default. The next provider request contains the old user and assistant messages. |
| `model: "azure-openai-responses/gpt-4.1"` | Rejects at open because that provider/model is no longer registered. |
| `model: "azure/gpt-4.1"` | Opens with the original id and the explicitly selected new model. No Azure generation request is sent. |

For both successful opens, the stream starts at sequence zero.
`Session.model()` and the opening `model` event both name the effective
model, including the fallback. The probe observes the opening event by
subscribing with `cursor: { sessionId, afterSeq: -1 }`. Hosts can therefore
detect the selection change instead of assuming the saved model survived.

This is native persistence and resume evidence with a synthetic transcript
and a scripted fallback model. It does not establish Azure network,
credential or cache compatibility, or behavior with no usable fallback.

## Other validation

On `exe-dev-openai/gpt-6-luna@llm`, all 11 applicable live cases passed:
conversation, multiple turns, shell-tool detail, busy and late control,
same-turn steer, queue as a spontaneous next turn, native abort, disposal
during a turn, cursor replay, resume and unknown-model rejection. Subagents
and process killing were inapplicable. The provider's incomplete pricing
table means token usage here is not billing-cost evidence.

Pi's simulated-provider behavior suite was 19/19 clean (17 passed and two
inapplicable skips), including withdrawal before dispatch. All eight
applicable vendor tests passed. No assertions or snapshots were weakened.
The ordinary `pi-upgrade-resume.ts` check also passed from 1.0.2 to 1.0.3:
native id, saved model and prior transcript survived; the reopened stream
began at sequence zero. That result applies to its unchanged provider id,
not the removed Azure provider.

## Release scope and reproduction

At the start, main and the `v0.20.3` tag both pointed to `f385b91`; both
npm packages were independently verified at 0.20.3. Today's new scope is
the Pi lockfile/pin upgrade, migration evidence and documentation. Other
runtimes' unchanged versions did not trigger new authenticated calls.

```sh
pnpm tsx experiments/runtime-versions.ts
pnpm tsx experiments/live-contract.ts pi --model exe-dev-openai/gpt-6-luna@llm
CI=true OAR_TEST=pi-aimock pnpm vitest run sea-trial/vendor
OAR_TEST=pi-aimock pnpm sea-trial
pnpm tsx experiments/pi-upgrade-resume.ts <checkout-with-pi-1.0.2>
pnpm tsx experiments/pi-azure-upgrade-resume.ts <checkout-with-pi-1.0.2>
pnpm run check
pnpm run build
```

Use the same OAR adapter source in the older checkout. Select isolated
executables with `OAR_CLAUDE_BIN`, `OAR_CODEX_BIN`, `OAR_KIMI_BIN` and
`OAR_ANTIGRAVITY_BIN`; managed launchers were not replaced. Pi and Cursor
versions come from their SDK dependencies. Raw inventories, reports and
voyage logs are retained under `oar-trial-run/runtime-check-2026-10-05/`.
