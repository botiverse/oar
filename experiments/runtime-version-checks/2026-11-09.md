`ff62e2fc` but remains open and unmerged. It is not the released behavior
above. The earlier [tool-index review](https://github.com/QwenLM/qwen-code/pull/16586#issuecomment-6722241500)
is a static finding about that proposed change, not an observed defect in
this released version.

After a stable release includes the final fix, rerun behavior, vendor tests
and the snapshot replay with both **thinking -> text -> tool_use** and
**text -> tool_use**. Compare message id, block index/type and tool call id

tool events and correct tool-input association. Only then document the first
verified version with consistent ids. Keep positional/type snapshot
compatibility for older versions. The current `reply-blocks` probe covers
thinking/text and plain-text controls, not those future tool transitions.
