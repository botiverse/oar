## Claude 2.1.316

[login-browser probe](../claude-login-browser/README.md) passed all three
Linux controls against a local OAuth stand-in: one normal opener, zero

independent verification of those particular conditions. No OAR cleanup
policy or hook behavior is changed by this daily update.

## OpenCode 2.2.5

### Native startup

The [OAR-free startup probe](../opencode-startup.ts) still reproduces
concurrent first-start failures:

| Scenario | Ready | Native failure |
| --- | --- | --- |
| Two sequential fresh starts | 2 / 2 | None |
| Four concurrent starts, fresh database | 2 / 4 | Both failures report `table account_state already exists` |
| Four concurrent starts, initialized database | 4 / 4 | None |

The failures exited 1, without a signal, after 376 and 382 ms. This is
the same native database-initialization failure tracked in
[issue 53879](https://github.com/anomalyco/opencode/issues/53879).
The startup script records failures without making its own exit status a
compatibility verdict. Sequential and warm controls do not establish that
every startup failure is fixed by preparation.

### Existing boundaries and MCP

The [boundary probe](../opencode-release-lines.ts) passed **nine of ten**
checks. Its cold catalog returned eight models; queueing, child attribution,
ordinary resume, prompt-option refusal, abort, disposal and native steer
refusal passed. The MCP cold resume still omitted the tool call.

The [independent native ACP probe](../opencode-mcp-resume-native.ts) called
echo in its new session and on **none of six cold resumes**. All seven
turns reported `end_turn`, and all seven processes logged an MCP connection.
The native transcript announced the echo tool initially, then removed it
on the first resume without adding it again. These connections do not prove
the model received the tool. The existing
[cold-resume issue](https://github.com/anomalyco/opencode/issues/54794)
remains open.

The local-provider [warm catalog control](../mcp-tools-catalog-changed.ts)
passed: alpha executed, beta replaced it and executed, and a later call to
removed alpha reached no handler. This does not resolve the cold-resume
failure. Both failing probes retained nonzero exit statuses and their
original evidence; neither was retried into a passing result.

The [2.2.4](https://github.com/anomalyco/opencode/releases/tag/v2.2.4)
and [2.2.5](https://github.com/anomalyco/opencode/releases/tag/v2.2.5)
notes describe configuration precedence, MCP output size and idle-service
lifecycle changes. Those changes do not establish a fix for the separately
observed startup and cold-resume failures. The v1-only vendor suite was not
applied to v2's different tools and prompts.

## Repeating the checks

Select the exact npm executables through `OAR_CLAUDE_BIN`,
`OAR_CODEBUDDY_BIN` and `OAR_OPENCODE_BIN`, then run:

```sh
pnpm tsx sea-trial/all.ts claude-aimock codebuddy-aimock opencode-aimock
OAR_TEST=claude-aimock pnpm vitest run sea-trial/vendor --maxWorkers 2
OAR_TEST=codebuddy-aimock pnpm vitest run sea-trial/vendor --maxWorkers 2
```

Run the Claude login and reserved-name probes using their file-header
commands. The CodeBuddy native scripts are
[`codebuddy-consecutive-prompts.mjs`](../codebuddy-native/2026-10-29/codebuddy-consecutive-prompts.mjs)
and [`codebuddy-acp-consecutive-prompts.mjs`](../codebuddy-native/2026-10-29/codebuddy-acp-consecutive-prompts.mjs);
pass the standalone executable and a delay of `0` or `1000` milliseconds.
Repeat the stream-json controls three times each.

The linked OpenCode probes retain their commands. The boundary and native
MCP-resume scripts use the external free model. Give the boundary script
isolated HOME/XDG directories; the other probes create their own isolated
configuration. Detailed outputs remain in ignored local artifacts.
[Selected observations](2026-10-31.json) retain versions, counts and native
diagnostic categories without account information.
