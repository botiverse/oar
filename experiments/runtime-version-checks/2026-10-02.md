## Pi upgrade and compatibility

The bundled coding-agent SDK and pi-ai dependency use **1.0.0**. The
workspace development dependency is pinned to that version, and the lockfile
updates only the eight Pi-family packages. Exact minimum-release-age
exceptions move to the tested releases. No adapter or public OAR interface
changes are required.

Pi's [1.0 release](https://github.com/earendil-works/pi/releases/tag/v1.0.0)
includes terminal UI, codemode, image generation and MCP changes. OAR still
uses the ordinary AgentSession SDK. The separate experimental
[Pi Durable harness](https://github.com/earendil-works/pi/blob/v1.0.0/packages/durable/README.md)
is not adopted by this dependency upgrade, and no new execution-recovery
guarantee is implied.

The same day's research run on OAR `0f2147a` (0.12.1), with Pi 1.0.0,
passed all 11 applicable live scenarios: basic, multi-turn, tool detail,
busy/late control, steer, queue, abort, mid-turn dispose, cursor replay,
resume and bad-model rejection. Subagents and process killing were
inapplicable. The Pi adapter is unchanged between that base and the release
base. This live evidence is reused, with its original provenance retained.
The current release checkout independently passed Pi's simulated-provider
behavior suite (18/18 clean, including inapplicable skips) and strict vendor
suite (8 cases). Claude and Codex strict vendor suites passed 12 and 10
cases respectively. Assertions and snapshots were unchanged.

The new [`pi-upgrade-resume.ts`](../pi-upgrade-resume.ts) probe starts a
session using SDK 0.99.2 in an older checkout, then resumes it with 1.0.0 in
a fresh process. The native session id and saved model survive; the next
provider request contains the earlier user and assistant messages plus the
new input. The new OAR stream starts at sequence zero. A local scripted
provider makes the check repeatable without login or model quota. This is
conversation continuity, not resuming interrupted tool execution.

## Cursor verification limit

The official Linux x64 archive was installed into an isolated workspace
directory. The executable reports `2026.10.01-e373342`, and OAR detects its
ACP entry point. Both requested live cases timed out at `authenticate`
after 30 seconds, before a conversation or model request. The native
`cursor-agent status` reports `Not logged in` on this host.

This is not a passing compatibility probe. No login was available to finish
the live check; the previous [Cursor evidence](../../docs/runtimes/cursor.md)
remains the live baseline. No Cursor adapter change or credential change was
made for this check.

## Reproduction and artifacts

Use the [inventory/smoke commands](2026-09-29.md#repeat-the-check) with the
versions and models above. Claude, Codex and Cursor were installed in
isolated directories and selected through `OAR_CLAUDE_BIN`,
`OAR_CODEX_BIN` and `OAR_CURSOR_BIN`; Kimi's existing isolated installation
used `OAR_KIMI_BIN`. Host-managed launchers were not replaced. Pi's version
is the SDK resolved from OAR's adapter, not a command named `pi` on PATH.

```sh
OAR_TEST=pi-aimock pnpm sea-trial
CI=true OAR_TEST=pi-aimock pnpm vitest run sea-trial/vendor
pnpm tsx experiments/pi-upgrade-resume.ts /path/to/oar-with-pi-0.99.2
```

Local evidence: `oar-trial-run/runtime-check-2026-10-02/`, including
`versions.json`, `versions-final.json`, `claude-2.1.287/`,
`codex-0.160.0/`, `cursor-2026.10.01/`, `pi-1.0.0/` and
`pi-upgrade-resume/`. Each live directory has a report and voyage logs;
`pi-1.0.0/provenance.json` identifies the earlier research checkout.
Raw logs are not committed. Pi's provider warned of missing pricing for
ten integration models, so monetary cost accuracy was not validated.
