# Runtime version check: 2026-11-24

Antigravity 1.5.16 passed the scheduled Linux, macOS and Windows ACP jobs.
All five failed jobs in the reporting window involved OpenCode. Two Windows
jobs failed during SQLite startup. Three candidate jobs exposed the same
skill-listing regression on OpenCode 2.4.1. The [selected evidence](2026-11-24.json)
includes original failures, the retry, frozen versions and Linux probe results.

## Antigravity

Google published 1.5.16 at 04:06 UTC. The scheduled run froze that version at
06:32 UTC and passed it on all three platforms on the first attempt. At the
evening check, the four official updater manifests matched the archive URLs
and SHA-512 digests already accepted in OAR. The release forwards child
permission requests and questions to ACP clients and adds global skill
discovery under `~/.agents/skills`, with `~/.gemini` taking precedence.
[Release notes](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.16),
[scheduled run](https://github.com/botiverse/oar/actions/runs/45341232470),
[baseline PR](https://github.com/botiverse/oar/pull/1170).

## Changed candidates

Four entries changed since the previous inventory. Factory 1.19.0 was
available at the morning freeze. CodeBuddy 2.186.0, Qoder 1.1.97 and Cursor
SDK 1.5.0 appeared later. The local checks used OAR `8ec51b3e` on Linux x64
with isolated homes and scripted providers.

| Candidate | Local result |
| --- | --- |
| Factory 1.19.0 | 20 behavior cases and 13 vendor tests passed. Native steering queued the message at end of turn, interruption discarded the queued request, and a resumed session completed its next turn. |
| CodeBuddy 2.186.0 | 17 behavior cases passed, three skipped, and nine vendor tests passed. The scheduled jobs tested 2.185.0. |
| Qoder 1.1.97 | The version check passed. Offline replay remains unavailable. The probe submitted zero prompts. |
| Cursor SDK 1.5.0 | The SDK compiled against OAR's host interface. All 12 local login scenarios and six configuration cases passed. The configuration probe preserved the synthetic login after disposal and reopen. |

The Cursor usage replay previously expected an empty frame after a model
call, an assertion that predates OAR's [per-call context reader](https://github.com/botiverse/oar/pull/926).
The corrected [probe](cursor-sdk-check.ts) observed 100 context tokens at call
completion and 100 input plus 20 output tokens at turn end on both pinned
1.4.1 and candidate 1.5.0. This replay uses synthetic events.

The [Cursor skill parity test](../../sea-trial/vendor/cursor-skills.vendor.test.ts)
failed on 1.5.0 in both fixtures before comparing any skills. Its copied-bundle
observer called `y.q6`; the new bundle uses `b.q6` to create the same context.
Changing only that reference in a diagnostic copy let the original assertions
pass. Native and OAR listings agreed on 19 valid items outside Git and 23
inside Git. Both OAR results marked the inventory as partial because the
fixtures included invalid skills. The scheduled three-platform Cursor jobs
passed with SDK 1.4.2. A three-platform 1.5.0 parity result still requires an
updated observer.

The window covers workflows created November 23 at 21:08:00 UTC through
November 24 at 21:07:59 UTC. It contains 26 runs and 27 attempts. Each job
ID is counted once. Two ordinary CI runs awaiting approval had zero jobs.

| Workflow | Runs | Attempts | Passed | Failed | Skipped | Cancelled |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |

| Frozen candidates | 1 | 1 | 39 | 3 | 0 | 0 |

- In ordinary CI and the platform matrix, Windows OpenCode 2.2.7 failed
  before the effort assertion. Its native log reported a disk I/O error
  while configuring the database 863 ms and 534 ms after session open
  began, respectively. Each trace recorded one closing peer and the database,
  WAL and shared-memory files present at rejection. Neither identified
  the failing file or an extended SQLite code. The ordinary job passed its
  same-head retry. [Original ordinary trace](https://github.com/botiverse/oar/actions/runs/45269895777/artifacts/14865121054),
  [retry](https://github.com/botiverse/oar/actions/runs/45269895777/job/138030458023),
  [platform trace](https://github.com/botiverse/oar/actions/runs/45319484528/artifacts/14887192548).
- In the frozen candidate workflow, OpenCode 2.4.1 returned a 764-byte skill
  list and reported `partial: false` after a configured plugin failed. Both
  assertions failed on Linux, macOS and Windows at `d4cfdc0b`. Later that day,
  OAR limited one-shot v2 skill discovery to 2.2.7 through 2.3.x and began
  returning `version_unsupported` on 2.4.0 and later before starting a server.
  [Diagnosis and controls](../opencode-skills/activation-2.4.1.md),
  [fix](https://github.com/botiverse/oar/pull/1171).
