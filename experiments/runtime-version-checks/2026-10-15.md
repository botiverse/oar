## Claude 2.1.300

The [official changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#21300)
includes headless compaction/resume fixes, MCP reconnection and tool-schema
handling changes, and background-command shutdown fixes. The existing
vendor and shared behavior suites passed against the real executable and
aimock. These are observations of the covered cases, not verification of
every upstream release-note claim.

The new `mcp-tools-list-changed.vendor.test.ts` passed: after replacing
`alpha` with `beta`, Claude lists the server again, but the next model
request still defines both tools. `mcpToolsListChanged: "additions"`
remains accurate.

The native `--mcp-config` path still silently drops all five reserved names
from [#395](https://github.com/botiverse/oar/issues/395):
`__proto__`, `__defineGetter__`, `__defineSetter__`, `__lookupGetter__`
and `__lookupSetter__`. Each was tested in its own process and fresh home.
All five returned a successful result with an empty `system/init`
`mcp_servers` list and no MCP tool in the captured provider request.
The control name `plainname` connected and offered `mcp__plainname__ping`.
OAR's common refusal remains necessary.

[`claude-reserved-mcp-names.ts`](../claude-reserved-mcp-names.ts) makes this
native check reproducible. It deliberately bypasses OAR's public name
guard, prints only server/tool names and native status, and cleans up its
processes and temporary configuration. The ordinary
`tests/refused-session-options.test.ts` separately checks that OAR rejects
these names before any runtime starts.

## Kimi Code 2.2.0

This is the TypeScript
[`@moonshot-ai/kimi-code` release](https://github.com/MoonshotAI/kimi-code/releases/tag/%40moonshot-ai/kimi-code%402.2.0),
not Python `kimi-cli`. Its notes include opt-in progress updates,
background-task wait behavior, resumed media handling and MCP configuration
validation. Comparing the two release tags with git found no changes to
`packages/acp-server/src` or `apps/kimi-code/src/cli/sub/acp.ts`; the ACP
package's dependency version and changelog changed. The underlying harness
did change, so native behavior was checked as well.

All nine applicable native vendor tests passed: session MCP servers on
creation/resume and configuration collisions, provider error evidence,
image-only input, additional directories and their resume refusal, and
tool-list changes. Kimi did not relist after the notification and still
offered only `alpha` on the next turn. Its `mcpToolsListChanged: "none"`
declaration remains accurate.

The shared behavior cases also passed through `kimiSession` with
`startKimiAimock`. That session-only subject omitted the standalone account
usage and model catalog readers; those two cases skipped, as did the two
steer cases because Kimi's ACP session has no steer operation. This run
does not establish real-account catalog or quota behavior.

## Reproduce

Select the isolated executables with `OAR_CLAUDE_BIN` and `OAR_KIMI_BIN`.
Use a fresh Claude configuration directory and omit inherited account
tokens when running its vendor/behavior suites; the Kimi vendor harness
provides its own fresh home and scripted provider configuration.

```sh
pnpm tsx experiments/runtime-versions.ts
OAR_TEST=claude-aimock pnpm vitest run sea-trial/vendor
OAR_TEST=claude-aimock pnpm sea-trial
OAR_TEST=kimi-aimock pnpm vitest run sea-trial/vendor
pnpm tsx experiments/claude-reserved-mcp-names.ts
CI=1 pnpm run check
pnpm run build
```

The full local check passed: typecheck, lint, 1,808 unit tests and all
applicable mock behavior cases. Both package builds passed as well.

The native checks ran on Linux only. They do not establish current
Windows/macOS behavior, real-account login behavior, or every new
upstream feature's behavior.
