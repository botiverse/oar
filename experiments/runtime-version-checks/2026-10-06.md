## Cursor host migration

**OAR 0.25.0 requires hosts using Cursor to install `@cursor/sdk@1.0.36`
alongside OAR.** The optional peer dependency remains an exact pin to the
SDK tested in CI. Keeping 1.0.35 in the host produces a peer dependency
conflict. The CLI depends on 1.0.36 itself. Hosts that do not use Cursor
still do not need this optional package. No session API or adapter change
was necessary, and this change does not include Cursor login support.

The workspace and OAR development dependency also pin 1.0.36. On
`gpt-5.4-nano`, all 12 applicable live scenarios passed: conversation,
multiple turns, shell tools, busy and late control, steer, queue, abort,
dispose mid-turn, cursor replay, resume, subagents and unknown-model
rejection. Killing a dedicated runtime process is inapplicable to the
in-process SDK. These runs test same-version resume, not a cross-version
Cursor conversation-store migration.

## Pi upgrade

The [Pi 1.0.4 changelog](https://github.com/earendil-works/pi/blob/v1.0.4/packages/coding-agent/CHANGELOG.md)
includes tool-selection glob patterns, MCP shutdown and OAuth client fixes,
codemode image handling, and retries for stalled Bedrock HTTP/2 streams.
The workspace pin and lockfile now select 1.0.4. OAR's existing SDK and
provider dependency ranges remain `^1.0.2`, so consumers may need to refresh
their lockfile. Package-manager release-age policies can also hold back a
fresh version; this workspace explicitly allows the selected Pi and Cursor
packages.

On `exe-dev-openai/gpt-6-luna@llm`, ten applicable live scenarios passed
on the first run. `tool-detail` initially received the provider's overload
error; an unchanged, targeted retry passed. Together these cover all 11
applicable cases; subagents and process killing are inapplicable. Both the
failed first report and the passing retry remain in the evidence directory.
Incomplete provider pricing means usage here is not billing-cost evidence.

[`pi-upgrade-resume.ts`](../pi-upgrade-resume.ts) passed from 1.0.3 to 1.0.4
in separate processes with the same OAR adapter source. The native id,
saved model and previous user/assistant messages survived, and the reopened
OAR record stream began at sequence zero. The provider was scripted; this
checks conversation continuity, not interrupted execution recovery.

The [1.0.3 Azure migration](2026-10-05.md#old-azure-sessions) still applies:
rename native provider configuration to `azure` and explicitly select
`azure/<model>` when resuming an old Azure session. Today's ordinary resume
probe does not add Azure network, authentication or cache evidence.

[official changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

[release notes](https://github.com/anomalyco/opencode/releases/tag/v1.18.34)
mention session identity headers on model requests and macOS codesigning.
The probe uses `opencode acp`; it does not validate the separate HTTP
server API or macOS packaging.

All applicable vendor tests passed without snapshot changes: Claude 12,
Codex 11, Pi 8. Each corresponding simulated-provider behavior suite was
19/19 clean, with only capability-based skips. No assertions, timeouts or

## Reproduction and release scope

At the start, main and `v0.24.0` pointed to `a3e1190`, and both npm packages
were independently verified at 0.24.0. The new release scope is the exact
Cursor SDK peer/dependency upgrade, Pi workspace resolution and updated
compatibility evidence. OpenCode is now included in the eight-core inventory;
unchanged runtime versions did not trigger fresh authenticated calls.

```sh
pnpm tsx experiments/runtime-versions.ts
pnpm tsx experiments/live-contract.ts claude --only basic,tool-detail,resume
pnpm tsx experiments/live-contract.ts codex --model gpt-6-luna --only basic,tool-detail,resume
pnpm tsx experiments/live-contract.ts cursor
pnpm tsx experiments/live-contract.ts opencode
pnpm tsx experiments/live-contract.ts pi --model exe-dev-openai/gpt-6-luna@llm
pnpm tsx experiments/live-contract.ts pi --model exe-dev-openai/gpt-6-luna@llm --only tool-detail
pnpm tsx experiments/pi-upgrade-resume.ts <checkout-with-pi-1.0.3>
# Repeat for claude-aimock, codex-aimock and pi-aimock:
CI=true OAR_TEST=pi-aimock pnpm vitest run sea-trial/vendor
```

Use the same adapter source in the older checkout. Point `OAR_CLAUDE_BIN`,
`OAR_CODEX_BIN` and `OAR_OPENCODE_BIN` at isolated versions of the native
executables; managed launchers were not replaced. Pi and Cursor versions
come from their actual SDK importers. Raw inventories, reports and voyage
logs are retained under `oar-trial-run/runtime-check-2026-10-06/`, including
`codex/` (unsupported default), `codex-supported-model/`, `pi/`,
`pi-tool-retry/` and `pi-upgrade/`.
