### Cursor 1.4.2 and the local pipe controls

The candidate passes 11 local login cases, six configuration controls and
native skills parity in Git and non-Git workspaces. The isolated fixture
uses a local backend and blocks external connections.

Its full check passes typecheck and lint, then reports 5,053 passing tests,
three failures and 652 skips. All three failures reproduce in the unchanged
`e1ed3abf` checkout: two extra-pipe reader diagnostics also report stdout
and stderr held open, and the paused-stderr control also reports stdout.
The holder process identities match the expected children.

After the other local suites stopped, five sequential reader-only rounds
still each fail the same two assertions. Their ten drain waits are
2,036 to 2,076 ms. Both files also reproduce the same three failures under
an isolated Node 24.22.0 installation. A standalone shell control shows
that the background child has fd 1/2 redirected to `/dev/null` but retains
two additional socket descriptors, fd 10/11; all three parent streams
remain open after 2.1 seconds. Here `sh` resolves to `/exe.dev/bin/sh`
and reports `sleep` as a builtin. The shell retains saved stdout/stderr
descriptors in that builtin holder, so OAR correctly reports held pipes.
The test incorrectly assumes those pipes close.
[PR 966](https://github.com/botiverse/oar/pull/966) redirects a subshell
that explicitly execs sleep, matching the existing late-writer control.
Applied to unchanged `e1ed3abf`, the two-file patch passes all 14 focused
tests with `CI=1` on this machine, without changing assertions. It is
subsequently merged as `694b640f`.
This is a fixture assumption, not a demonstrated Cursor incompatibility.

The original failures remain recorded alongside that correction. This
report changes no assertions or production code. Cursor 1.4.2 still
requires its own reviewed upgrade and platform checks.
