## Cursor 1.0.40

The root development dependency, OAR's exact optional peer and development
dependency, CLI dependency, release-age exceptions and lockfile now use
**`@cursor/sdk@1.0.40`**. Hosts using Cursor must install that version beside
OAR. The CLI installs it itself; hosts without Cursor still need no SDK.
User-facing version diagnostics and installation examples follow the pin.

The installed package's `dist/esm/agent/options.d.ts` and `agent.d.ts`
declarations add optional `teamId` parameters for agent, account and catalog
calls. Its documented native behavior omits the
team header without a valid positive integer; OAR does not expose this new
option. The package also adds local-store failure recovery declarations.
These are package observations, not claims that multi-team routing or
storage-failure recovery was exercised by today's probes. Existing OAR
session/auth calls remain compatible without an adapter behavior change.

The real SDK's login/logout probe passed its network guard and all 11
scenarios with synthetic credentials and a loopback backend. Cancel/deadline
while polling or minting, late-save refusal, logout and the API-key override
boundary remain correct. No actual login was repeated.

Live checks reused the existing xxwork login under the owner's standing
small-test authorization, with `gpt-5.4-nano`. All 12 applicable session
scenarios passed on the first run: conversation, tools, busy/late control,
steering, queueing, abort, disposal, replay cursor, resume, children and bad
model handling. `kill-runtime` is skipped for this in-process SDK. All three
tool-selection rounds passed: baseline shell and MCP execution, then new
and resumed restricted sessions with read still usable. The host MCP
handler ran once in the baseline and never in either restricted round.

The 18 native run results report usage for 16 runs: 268,773 input tokens,
205,312 cache-read tokens and 3,084 output tokens, **477,169 reported tokens**
in total. Output includes 1,939 reasoning tokens; cache-write is zero. Two
cancelled runs omit usage. These are reported counts, not a complete billing
estimate or independently measured child charges. Account-identifying
information and raw voyages stay local.

## Claude 2.1.306

[The native changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#21306)
and the intervening 2.1.305 entry describe ToolSearch/gateway fixes and MCP
server precedence changes. Today's 51 native tests cover MCP attachment and
resume, tool search/list changes, tool denial, input, children, structured
output, effort, service tiers, directories, failure redaction and opening
hooks. All passed, as did the 17 applicable shared behavior cases. The
reserved-name probe again excluded all five refused names and discovered
the ordinary control tool. Default Claude startup traffic remained enabled
for the vendor and behavior runs.

The Linux login-browser probe passed all three modes with synthetic local
OAuth. The default opener ran once; `openBrowser: false` opened no browser;
the failing opener ran once without falling back to the default browser.
Each mode emitted one URL and one code prompt, completed a verified PKCE
exchange, and returned `logged_in` from login and subsequent status. This
new-version check covers Linux only; the earlier cross-platform evidence
and its macOS completion limitation are unchanged.

## Kimi 2.3.0

[The official release](https://github.com/MoonshotAI/kimi-code/releases/tag/%40moonshot-ai/kimi-code%402.3.0)
includes qualified plugin skill names, session hook working-directory fixes
and optional deferred MCP discovery. These release notes do not establish
that OAR exposes those features; the selected ACP interface's independent
inventory methods remain unsupported.

The first native suite passed 10 tests and failed the new/cold-resume hook
case during `initialize`, at the test's shortened 2,000 ms `requestTimeoutMs`
in [`kimi-open-hooks.vendor.test.ts`](../../sea-trial/vendor/kimi-open-hooks.vendor.test.ts).
[OAR's Kimi request default](../../packages/oar/src/runtimes/kimi/session.ts)
is 30 seconds, so this failure does not establish that users would hit the
same timeout. The other hook case passed. Rerunning only the hook file
passed both tests, with the same assertions, hook delays and timeouts. The
initial failure is retained and its cause is unlocated; a passing recheck
does not establish a startup fix.
All 11 applicable native cases therefore have passing evidence. The shared
behavior subject passed 15 cases and skipped four.

A local runner initially selected nonexistent `kimi-aimock` in the shared
backend registry and exited before starting a runtime. The corrected runner
uses the existing `startKimiAimock`, `kimiSession` and shared cases directly,
as the earlier Kimi daily probe did. This invocation error is separate from
the test's native initialization timeout above. No test conditions were relaxed.

## OpenCode 2.1.2

The [native tag](https://github.com/anomalyco/opencode/releases/tag/v2.1.2),
registry and binary identify 2.1.2. No behavioral fix is inferred from the
version number. The first shared behavior run passed 15 cases, skipped four
and took 15.5 seconds. Complete initial stderr, the native log/state and
elapsed time were saved before cleanup. Earlier intermittent native startup
failures were not reproduced; they remain unexplained.

The catalog probe returned ten models and refused both `appendSystemPrompt`
and `systemPrompt`. Warm MCP discovery, alpha execution, replacement with
beta, beta execution and deliberate use of removed alpha all behaved as
before. Removed alpha was rejected without reaching the host; the handler
saw one alpha call before replacement and one beta call afterward.

The independent native ACP probe used free `opencode/big-pickle`, no OAR
imports and no account. Fresh creation and all six cold resumes executed
the echo tool. However, every resume still persisted a removal notice 43 to
55 ms after its prompt, then an addition 1.87 to 2.60 seconds after it.
Successful calls do not eliminate this inconsistent catalog window or
establish a fix for [OAR #371](https://github.com/botiverse/oar/issues/371).
The previous 2.1.0 run omitted the call on all six resumes; both outcomes
are preserved rather than replacing the earlier failure evidence.

## Validation and reproduction

Claude and Kimi model traffic, plus OpenCode behavior/list-change traffic,
used local scripted providers with disposable HOME/configuration directories
and no account. The free OpenCode resume probe and the authorized Cursor
live checks are explicitly separated above.

- `OAR_TEST=<claude|kimi>-aimock pnpm vitest run sea-trial/vendor --maxWorkers=2`;
  the Kimi recheck selected only `sea-trial/vendor/kimi-open-hooks.vendor.test.ts`.
- `OAR_TEST=claude-aimock pnpm sea-trial`; Kimi uses `startKimiAimock` with the
  same shared cases; OpenCode uses `experiments/acp-aimock-behavior.ts opencode`.

  `pnpm tsx experiments/claude-login-browser/probe.ts <absolute-binary> 2.1.306`.

  login, `experiments/live-contract.ts cursor --model gpt-5.4-nano --out <out>`
  and `experiments/cursor-disallowed-tools.ts`.
- `pnpm tsx experiments/opencode-release-lines.ts <binary> <cwd> <out> catalog appendSystemPrompt systemPrompt`,
  `experiments/mcp-tools-catalog-changed.ts opencode`, and
  `node experiments/opencode-mcp-resume-native.ts <binary> <out> 6`.

`CI=1 pnpm run check` passed: typecheck, lint, 1,898 unit tests and all
19 mock behavior cases. `pnpm run build` and `pnpm run clean-install`
also passed. The packed-install check verified that OAR loads without the

Cursor. The branch was checked against current main `b9a025f` before commit.
