## Pi 1.0.2

The [upstream changelog](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/CHANGELOG.md)
adds per-thinking-level sampling configuration in 1.0.2. The intervening
1.0.1 includes MCP project overrides and provider retry fixes. This change
updates the workspace SDK pin, OAR's Pi SDK and provider dependency ranges,
and the lockfile. It does not change OAR's public contract or adopt the
separate experimental Pi Durable harness.

With `exe-dev-openai/gpt-6-luna@llm`, all 11 applicable live cases passed:
basic conversation, multiple turns, shell-tool details, busy and late
control, same-turn steer, queue as a spontaneous next turn, native abort,
dispose during a turn, cursor replay, resume and unknown-model rejection.
Native subagents and process killing were inapplicable. Reported token
usage was nonzero; the provider extension warned that its pricing table is
incomplete, so these runs are not billing-cost evidence.

The Pi simulated-provider behavior suite was 19/19 clean (17 passed and
two inapplicable skips), including withdrawal before dispatch. All eight
applicable vendor tests passed. No assertions or snapshots were changed.

The existing `pi-upgrade-resume.ts` probe created a session with SDK 1.0.0
and resumed it in a separate process with 1.0.2, with the same OAR adapter
source on both sides. It retained the native session id, saved model and
prior user/assistant messages in the next provider request. The reopened
OAR stream began at sequence zero. This establishes conversation continuity,
not recovery of unfinished execution or an OAR-owned queue.

## Cursor inventory follows the host

Since OAR 0.20.0, the host installs `@cursor/sdk` and supplies its import to
`createCursorRuntime`. The repository's host is
`sea-trial/harness/runtimes.ts`; the inventory now resolves Cursor's package
manifest from that file instead of from OAR's adapter. Pi still resolves
from its adapter. This keeps each reported version tied to the dependency
that actually supplies the runtime when workspace package versions differ,
without loading the SDK or making an authenticated request.

The SDK's [official npm metadata](https://www.npmjs.com/package/@cursor/sdk)
reports 1.0.35, matching the host's installed pin. The prior Cursor CLI
version is historical evidence, not the current runtime. The
[Cursor page](../../docs/runtimes/cursor.md) records the October 3 SDK live
battery and the separate native authentication and platform limits. Those
checks were not repeated today.

## Release scope and reproduction

Both npm packages were independently verified at 0.20.0 at the start.
Main contained only the additional Cursor deployment documentation in
[PR 119](https://github.com/botiverse/oar/pull/119). This change prepares
0.20.1 with Pi 1.0.2 and the corrected inventory. The unrelated, still-open
Cursor type-export PR 120 is not part of this release.

```sh
pnpm tsx experiments/runtime-versions.ts
pnpm tsx experiments/live-contract.ts claude --model haiku --only basic,tool-detail,resume
pnpm tsx experiments/live-contract.ts pi --model exe-dev-openai/gpt-6-luna@llm
CI=true OAR_TEST=claude-aimock pnpm vitest run sea-trial/vendor
CI=true OAR_TEST=pi-aimock pnpm vitest run sea-trial/vendor
OAR_TEST=claude-aimock pnpm sea-trial
OAR_TEST=pi-aimock pnpm sea-trial
pnpm tsx experiments/pi-upgrade-resume.ts <checkout-with-pi-1.0.0>
pnpm run check
pnpm run build
```

Use `OAR_CLAUDE_BIN`, `OAR_CODEX_BIN`, `OAR_KIMI_BIN` and
`OAR_ANTIGRAVITY_BIN` to select the isolated executables. Pi and Cursor
versions come from SDK dependencies, not commands on PATH. Managed host
launchers were not replaced. Raw inventories, reports and per-scenario
voyage logs are retained under `oar-trial-run/runtime-check-2026-10-04/`.
