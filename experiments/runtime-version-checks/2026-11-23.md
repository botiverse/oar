# Runtime version check: 2026-11-23

Antigravity 1.5.14 passed the scheduled Linux and macOS jobs and the
Windows retry. OAR advanced its ACP baseline to 1.5.14 in
[PR #1149](https://github.com/botiverse/oar/pull/1149). The scheduled run
finished with a separate Windows unit failure in the Cursor SDK job. On
Linux, OpenCode 2.4.1 omitted all six fixture skills that 2.3.2 returned.
The [selected evidence](2026-11-23.json) records all 20 failed jobs,
including original attempts, and the separate Linux candidate probes.

## Antigravity

The November 23 candidate freeze at 06:42 UTC selected 1.5.14. On Windows,
the second skills listing omitted `oar-cli`, matching the intermittent
[listing issue](https://github.com/botiverse/oar/issues/918). All three
Antigravity jobs passed at 1.5.14 on the second attempt. Both Windows
Cursor SDK attempts failed an Antigravity plan fixture that read a missing PID file. OAR subsequently changed those tests
to wait for fixture readiness. [Scheduled run](https://github.com/botiverse/oar/actions/runs/45125855663),
[fixture fix](https://github.com/botiverse/oar/pull/1150).

Google released 1.5.15 at 06:59 UTC, after the freeze. OAR's native tests
for that version showed that non-daemon commands and subagents keep the root
prompt open. The wait can be silent after the launch tool call completes,
and the root receipt excludes child usage. Linux and macOS gained exact-version
file-based skill discovery. [ACP and skills measurements](https://github.com/botiverse/oar/pull/1145).

The next release, 1.5.16, appeared on November 24 at 04:06 UTC, after the
reporting cutoff. All four official updater manifests reported 1.5.16 during
the follow-up. On Linux it passed 18 shared behavior cases and 19 vendor
tests. An isolated OAR skills query with zero prompts found a unique skill
in `~/.agents/skills` and returned the `~/.gemini` description when both
roots defined the same name. OAR uses the native listing for this version.
The release also documents forwarding child approval requests in ACP.
[Release notes](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.16).

## CI observations

The window covers runs created from November 22 at 21:08:00 UTC through
November 23 at 21:07:59 UTC. All 69 attempts from 65 runs are included.
Each job ID is counted once.

| Workflow | Runs | Attempts | Passed | Failed | Skipped | Cancelled |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Ordinary CI | 43 | 46 | 867 | 14 | 51 | 47 |
| Windows ACP observation | 17 | 17 | 33 | 1 | 17 | 0 |
| Frozen candidates | 1 | 2 | 81 | 3 | 0 | 0 |
| Platform matrix | 4 | 4 | 19 | 2 | 0 | 0 |

- In ordinary CI, Windows OpenCode v2 exited during four behavior jobs,
  including a same-head retry. The manual Windows platform shard also saw
  an exit during disposal. The scheduled macOS shard recorded a Claude
  fetch failure before that runtime's tests started. One cancelled platform
  dispatch created no jobs. [Windows retry](https://github.com/botiverse/oar/actions/runs/45235835795),
  [scheduled macOS run](https://github.com/botiverse/oar/actions/runs/45106120342).
- Windows recorded missing Antigravity fixture PID files, a CI script
  failure and two Pi reader timeouts within one job. The Pi fix passed the
  Windows vendor group on main. A separate OpenCode provider readiness
  assertion measured 3,005 ms against a 2,800 ms bound. A DSH listing
  timeout omitted the expected lock path, and a Codex tool list lacked the
  expected MCP entries after clearing a session deny list.
  [Pi reader fix](https://github.com/botiverse/oar/pull/1152),
  [Codex job](https://github.com/botiverse/oar/actions/runs/45232261187/job/137894745337).
- Three ordinary jobs failed Kimi tests covering native skill discovery,
  the Windows KAP missing-executable error, and Linux CLI account usage.
  The account-usage job passed on retry. [Kimi skill fixture fix](https://github.com/botiverse/oar/pull/1147),
  [KAP spawn fix](https://github.com/botiverse/oar/pull/1163).
- In the Windows ACP observation, Grok's OAR installation and npm-wrapper
  launches initialized. The Node launcher timed out at 15 seconds, and the
  diagnostic found a surviving owned process during cleanup.
  [Original job](https://github.com/botiverse/oar/actions/runs/45244870725/job/137938874172).
