## OpenCode 2.2.3

### Native startup

The shared behavior run passed all 15 applicable cases, but the independent
[startup probe](../opencode-startup.ts), without OAR or a model, still
reproduced two failures among four simultaneous first starts:

| Scenario | Ready | Native failure |
| --- | --- | --- |
| Two sequential fresh starts | 2 / 2 | None |
| Four concurrent starts, fresh database | 2 / 4 | One `database is locked`; one `table account_state already exists` |
| Four concurrent starts, initialized database | 4 / 4 | None |

Both failing processes exited 1, without a signal, after 1,247 and 1,432 ms.
This confirms the native errors described in
[upstream #53879](https://github.com/anomalyco/opencode/issues/53879).
They reproduce in the tested 2.2.1 and 2.2.3 releases; 2.2.2 was not tested.
Passing sequential/warm controls do not prove a general warmup fix. OAR
adds no startup retry or lock in this change. No additional upstream
version-only comment was posted.

### Existing boundaries and MCP

The [boundary probe](../opencode-release-lines.ts) passed **nine of ten**
checks. Its cold catalog returned eight models. Queueing, child attribution,
ordinary resume, unsupported prompt options, abort, disposal and native
steer refusal passed. The MCP cold-resume check omitted the tool call.

The [independent native ACP probe](../opencode-mcp-resume-native.ts) called
echo in its new session, then omitted it on **all six cold resumes**. Each
resume still reported `end_turn`, and every process logged an MCP
connection. The saved native transcript added the tool in the first turn,
then removed it on the first resume without a later re-addition. Connection
success is therefore not evidence that the model received the tool.
[Upstream #54794](https://github.com/anomalyco/opencode/issues/54794) remains
open.

The local-provider [catalog-change control](../mcp-tools-catalog-changed.ts)
passed: alpha executed, replacement beta was announced and executed, and
removed alpha reached no handler. That warm-connection result does not
resolve the cold-resume failure. The v1-only vendor suite was not applied
to v2's different tools and prompts.
