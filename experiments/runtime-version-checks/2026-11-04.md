## Kimi 2.5.0

The existing MCP regression opens a session with stdio and HTTP echo servers,
calls both, disposes the process, then resumes with the same explicit servers
and calls the stdio echo tool again. Those configured calls succeed. A further fresh-process
resume omits `mcpServers`; its provider request still declares
`mcp__echo__echo` and `mcp__remote__echo`, where the test expects no MCP tools.
This is a tool-inventory observation, not evidence that the omitted-configuration
turn executed either tool.

The focused unchanged test was repeated against both native versions:

| Version | Tools offered after resume without MCP configuration | Test result |
| --- | --- | --- |
| 2.4.1 | None | Pass |
| 2.5.0 | Both saved echo tools | Fail |

The full 2.5.0 vendor run fails at that same assertion and passes its other ten
applicable cases. All fifteen behavior cases and four synthetic OAuth/login
controls pass. Both published bundles convert an absent or empty ACP server
list to an undefined restore option; that alone does not explain the changed
persistence. Root cause and the intended empty-configuration contract need a
separate investigation. No product, test expectation or Kimi CI pin is changed.
This does not revisit the separate shared-process admission refusal.

**Follow-up, November 5:** the [native investigation](https://raft-artifacts.com/p/open-agent-runtime/kimi-2-5-mcp-resume)
separates declarations from execution. Kimi 2.5.0 persists the initial tool list,
but its actual MCP tools follow the current resume configuration. Omission or an
empty list leaves old names advertised while their calls fail. Renamed servers'
new tools execute but are not advertised; same-name replacements use the new
configuration. The contrast with 2.4.1 and a single-expression diagnostic change
locate the mismatch in the choice of initial declarations. This is not evidence
that old servers or credentials were restored. OAR keeps the original assertion
and 2.4.1 CI pin until an upstream fix passes the same controls, without filtering
the model's tool list or blanket-refusing resumed MCP configuration.

passing diagnostic control; it is not substituted for latest in CI.

## agy CLI 1.5.0: new public ACP entry point

The official [1.5.0 changelog](https://github.com/google-antigravity/antigravity-cli/blob/c994f07d241d3b3b1902d5705008092beb00e099/CHANGELOG.md)
announces `agy acp`, including a second prompt during a turn as steering.
This is a different entry point from both stream-json and the separately
packaged ACP 1.4.5 server. The current [stream-json documentation](https://antigravity.google/docs/cli/headless#unsupported-messages)
still rejects control envelopes.

The official Linux archive was verified against its manifest's SHA-512. Version
and help report 1.5.0 and the public `acp` command. The new
[handshake probe](../antigravity-cli-acp-handshake.ts) uses a temporary home
inside a network-isolated namespace, without credentials, authentication or a
prompt. Its actual initialize response identifies `Antigravity ACP Server`
1.5.0, protocol 1. It advertises resume/load/close/list, images, additional
directories, logout and the Antigravity append-prompt metadata.

Only initialization was exercised. Advertised capabilities and changelog
claims do not establish working session opening, steering, cancellation,
permissions, MCP, resume or cleanup. OAR's transport remains the separate ACP
server. This new public interface is evidence for a separately scoped adapter
comparison, not proof of replacement compatibility.

## Repeating the checks

Install the named versions into isolated prefixes and point `OAR_CLAUDE_BIN`,
`OAR_KIMI_BIN`, `OAR_QODER_BIN` and `OAR_QWEN_BIN` at absolute executables.
Use their matching behavior backend and vendor selector, for example:

```sh
OAR_TEST_REQUIRE_AVAILABLE=1 pnpm tsx sea-trial/all.ts kimi-aimock
OAR_TEST=kimi-aimock pnpm vitest run sea-trial/vendor --maxWorkers 2
OAR_TEST=kimi-aimock pnpm vitest run sea-trial/vendor/mcp-servers-acp.vendor.test.ts \
  -t 'a stdio and an http server attach'
pnpm tsx experiments/qoder-native/replay-catalog.ts /absolute/qodercli 1.1.83
node experiments/antigravity-cli-acp-handshake.ts /absolute/antigravity
```

2.4.1 only as a diagnostic control. The [Qwen protocol](../qwen-native/probe.ts)
and [lock](../qwen-native/lock-lifetime.ts) probes, [Claude login probe](../claude-login-browser/probe.ts)
and [Cursor offline probe](../cursor-summarize-force-offline.ts) are unchanged.
Cursor probes load the SDK installed in the worktree; invoke direct `tsx` for
that temporary install and restore 1.2.0 before repository checks. The agy
handshake requires Linux and bubblewrap.
