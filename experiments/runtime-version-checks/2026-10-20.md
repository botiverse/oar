## Claude 2.1.304

The [official changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#21304)
enables tool search by default behind a custom `ANTHROPIC_BASE_URL`, with a
retry without it when a gateway returns 400 or 422. The initial vendor run
passed 47 tests and failed the tool-list observation, which assumed every
tool's schema appeared in the provider's `tools` array. The ordinary-name
control in the MCP name probe failed for the same reason. An otherwise
identical 2.1.303 control still sent the schema directly.

On 2.1.304 the server was connected. The initial request carried ToolSearch
and a placeholder, with the MCP names announced as searchable deferred
tools. Scripted search returned a native `tool_reference`, the next request
contained the schema, and a subsequent call executed the host handler and
returned its unique output. This is deferred loading, not missing tools.

The regression replaces alpha with beta after loading and executing alpha.
It also includes a third tool that is removed before ever being loaded:

| Observation after replacement | Result |
| --- | --- |
| MCP notification | Claude lists again |
| Searchable catalog | Beta added; alpha and the never-loaded tool withdrawn |
| Search for beta, then call it | Schema loaded; beta handler executes |
| Previously loaded alpha definition | Still in subsequent provider requests |
| Search for both removed tools | No match |
| Forced call to alpha | Native unknown-tool error; no host handler runs |

`mcpToolsListChanged: "additions"` therefore stays unchanged. Testing only
never-loaded tools would overstate removal support. The general
list-change probe now loads Claude's tools before each turn ends; a
separate native test pins the full search/load/call/removal chain. Catalog
observations fold explicit native availability and withdrawal announcements
in order, not arbitrary names found in the conversation history. No harness
sets `ENABLE_TOOL_SEARCH=false` to recover the old behavior.

The revised vendor suite passed all 49 applicable tests. Shared behavior
passed 17 cases, with account usage and catalog-dependent effort enumeration
skipped. All six MCP name probes passed: `plainname` connected and its tool
was searchable, while the five reserved names remained absent from both
the initialization server list and direct/deferred tool catalogs. OAR's
existing refusal remains necessary.

## OpenCode 2.1.0

The native executable reports `opencode v2.1.0`, matching npm `@opencode/cli`.
The catalog returned ten models. Both unsupported prompt options still
refused explicitly. The running-session MCP probe relisted, announced beta
and withdrew alpha in a Code Mode update, executed beta, and rejected a
forced call to removed alpha before reaching its handler. Old alpha text
remains in history; the later withdrawal is the current catalog evidence.

### Unlocated startup failures recurring across versions

The first shared behavior run passed 14 cases, skipped three and failed two
while opening the native process: `session.query-readbacks-carry-stream-seq`
and `session.steer-after-end`. Both reported
`Standalone server exited before reporting readiness`, followed by ACP
process exit 1. The latter never reached the capability check that would
normally skip it.

A rerun with the same cases, timeouts and concurrency passed 15 and skipped
four. It additionally copied native state before cleanup for diagnosis.
The initial stderr and failing traces remain evidence; a passing rerun does
not identify or fix the cause. Similar first-run failures were recorded on both release lines on
[October 17](2026-10-17.md#opencode).
First initialization or a startup race is a hypothesis, not a finding.
Future version checks should retain complete first-start stderr, native
logs and elapsed time before any retry or cleanup.

### Cold MCP resume remains broken

The unchanged [standalone ACP probe](../opencode-mcp-resume-native.ts) imports
no OAR code. A fresh session called the stdio echo tool, but **all six cold
resumes failed to call it**. Native logs showed the server reconnecting with
one tool on every round. The database held a removal notice written during
the first resume, without a subsequent addition notice restoring the tool.
The probe's nonzero exit is the expected unresolved failure, not a pass.
This corroborates the existing catalog problem; it does not establish
that every 2.1.0 resume fails.

## Validation and reproduction

`CI=1 pnpm run check` passed: typecheck, lint, 1,867 unit tests and the
mock behavior suite. The final focused Claude tests also passed after the
new case was isolated in its own configuration and working directory.

CI exposed a separate observation bug: the capture also contains Claude's
startup `/api/hello` request, which has no tool catalog. Running locally with
normal startup traffic reproduced that failure. The regression now selects
the Messages request for the current prompt and the request carrying each
tool result by call id, rather than global request positions. Unit coverage
includes startup probes, token counts, historical prompts and unrelated
model requests. The default-traffic native run passes with the same catalog
and handler assertions.

Install dependencies once, select the separate executables with
`OAR_CLAUDE_BIN` and `OAR_OPENCODE_BIN`, and run under disposable HOME and
configuration directories with inherited provider credentials cleared.
The aimock helpers supply their own local endpoint and dummy key:

```sh
OAR_TEST=claude-aimock CI=1 node node_modules/vitest/vitest.mjs run sea-trial/vendor --maxWorkers=2
OAR_TEST=claude-aimock node --import tsx sea-trial/main.ts
node --import tsx experiments/claude-reserved-mcp-names.ts
node --import tsx experiments/acp-aimock-behavior.ts opencode
node --import tsx experiments/opencode-release-lines.ts "$OAR_OPENCODE_BIN" "$probe_home" "$evidence_dir" catalog appendSystemPrompt systemPrompt
node --import tsx experiments/mcp-tools-catalog-changed.ts opencode
node experiments/opencode-mcp-resume-native.ts "$OAR_OPENCODE_BIN" "$evidence_dir" 6
```

Invoke installed tools directly when changing HOME, so pnpm does not select
a different package store. The cold-resume probe uses the free native
provider; the other commands above use local scripted responses.
