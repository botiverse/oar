## Cursor 1.0.38

The root development dependency, OAR's exact optional peer and development
dependency, CLI dependency, pnpm release-age exceptions and lockfile now use
1.0.38. Hosts using Cursor must install **`@cursor/sdk@1.0.38`** alongside
this OAR version. The CLI carries it itself; hosts without Cursor still do
not need the SDK.

The installed package changes Zod from a dependency to a peer,
`^3.25.0 || ^4.0.0`; this workspace resolves Zod 4.4.3. Its declarations use
`zod/v3`. The model declarations add optional `ModelSelection.maxMode` and
variant `isMaxMode`; the bundle derives max mode from catalog variants and
preserves a resolved selection. OAR's existing session/auth surface remains
compatible without an adapter change. These probes use `gpt-5.4-nano` and do
not establish behavior for every max-mode variant.

Bundle inspection also found a new background-shell `onCleanup` callback
that clears the 24-hour timer on completion or abort. The independent live
recheck in [PR #428](https://github.com/botiverse/oar/pull/428) verified the
tool-timeout and steer cases, plus `agent.close()` while a backgrounded
`sleep 121` still ran: every process exited about one second after close,
with no leftover `sleep`. This branch retains that merged evidence in the
[runtime page](../../docs/runtimes/cursor.md). These dedicated exit probes
were performed separately from the daily battery and usage totals below.

The real SDK's login/logout probe passed the network guard and all 11
scenarios against a loopback substitute, with disposable homes. Success,
cancel/deadline during polling or minting, late-save refusal, logout and the
API-key override boundary remain as documented. No real login was repeated.

The live battery reused the existing xxwork login under the owner's standing
small-test authorization. Eleven scenarios passed on the first run. The
abort scenario failed its expectation because the model changed the requested
`for i in $(seq 1 40); do sleep 1; done` into a loop containing `:`. The shell
finished in about one second; the native run finished at record 383, before
abort at 384. OAR correctly rejected that late abort with `no_active_turn`.
The original failure was retained.

Only abort was rerun, with the same script, model, assertions and timeouts.
This time the native shell arguments contained `sleep 1`; abort was accepted
before the SDK returned `status: "cancelled"`, and the outcome was `aborted`.
A subsequent abort was refused. All 12 applicable scenarios therefore have
passing evidence; `kill-runtime` remains skipped because this SDK runs in the
host process. Dispose during a run, steer, queue, replay cursor, resumed
identity/model/history and subagent attribution also passed.

The separate tool-selection probe executed shell and the host MCP callback
in its baseline. New and resumed restricted sessions executed only read;
the callback count remained one. All three rounds passed.

Native `cursor/run_result` records from 19 runs contain usage for 17:
292,328 input tokens, 208,384 cache-read tokens and 4,282 output tokens,
**504,994 reported tokens** in total. Output includes 2,854 reasoning tokens.
The two cancelled runs omitted usage. These are reported counts, including
the failed abort setup and its recheck, not a complete billing estimate;
child accounting is whatever the SDK includes in the root run. No separate
charge was inferred. Raw voyages and account-identifying details remain local.

## OpenCode

Both release lines remain separate. The
[v1.19.3 release notes](https://github.com/anomalyco/opencode/releases/tag/v1.19.3)
describe reasoning-variant configuration changes. The 2.0.32 version was
confirmed through the `@opencode/cli` registry entry and its binary; no matching
GitHub release entry was found. No unobserved v2 changelog was inferred.

The first shared-session runs had two opens exit with code 1 on each line:
v1 in query readbacks and observer isolation; v2 in single-active-turn and
abort. The other applicable cases passed. The initial harness recorded only
`ACP process exited with code 1`, without native stderr. Rerunning each line
with a wrapper that preserves stderr passed the unchanged cases and timeouts:
17 passed / 2 skipped for v1, 15 passed / 4 skipped for v2. The startup exits
were not reproduced or assigned a cause; a passing rerun does not explain
them. Original traces and diagnostic runs are retained locally.

The first v2 model query failed natively with
`ServiceUnavailableError: Location plugins did not finish activating`.
Direct `models --standalone` runs from fresh homes then succeeded on both
2.0.32 and the prior 2.0.30, returning the same ten IDs in about two seconds.
The unchanged OAR catalog/refusal probe also passed on recheck: ten models,
and both system-prompt options refused. No timeout, retry policy or adapter
behavior was changed.

V1's prompt-options probe passed replacement, append, saved-agent resume,
literal text, permission preservation and configuration conflict checks.
Its OAR catalog probe returned ten entries; separate native inventories
varied between ten and twelve. These are runtime catalog snapshots, not a
fixed promised model count or proof that a version added or removed an ID.

The v2 MCP probe warmed discovery, called alpha, replaced it with beta,
called beta, then deliberately called removed alpha. The model received the
new catalog notice including the explicit removal; beta executed and removed
alpha failed locally without reaching the host. The host saw exactly one
alpha call before replacement and one beta call afterward.

[Upstream issue 54794](https://github.com/anomalyco/opencode/issues/54794)
remains open with no newer response or posted fix. The cold-resume MCP race
tracked in [OAR #371](https://github.com/botiverse/oar/issues/371) remains open;
today's in-session list-change check does not resolve it. No account or
billable model was used for today's OpenCode probes.

## Validation and reproduction

Use independent binaries through `OAR_CLAUDE_BIN`, `OAR_GROK_BIN` and
`OAR_OPENCODE_BIN`, with temporary HOME/XDG/configuration directories. Install
dependencies before switching to that environment. The commands are:

- `OAR_TEST=<claude|grok|opencode>-aimock pnpm vitest run sea-trial/vendor`
  (OpenCode v1 only for this vendor suite).
- `OAR_TEST=claude-aimock pnpm sea-trial` and
  `pnpm tsx experiments/acp-aimock-behavior.ts <grok|opencode>`.
- `pnpm tsx experiments/claude-reserved-mcp-names.ts`,
  `experiments/grok-prompt-options.ts` and `experiments/opencode-prompt-options.ts`.
- `pnpm tsx experiments/opencode-release-lines.ts <binary> <cwd> <out> catalog`;
  add `appendSystemPrompt systemPrompt` for v2, without model requests.
- `pnpm tsx experiments/mcp-tools-catalog-changed.ts opencode` on v2.
- `pnpm tsx experiments/cursor-login/probe.ts` without a real account.
- With an authorized Cursor login,
  `pnpm tsx experiments/live-contract.ts cursor --model gpt-5.4-nano --out <out>`
  and `pnpm tsx experiments/cursor-disallowed-tools.ts`. The focused recheck
  uses `--only abort` and a separate output directory.

`CI=1 pnpm run check` passed: typecheck, lint, 1,840 tests and the mock
behavior suite. `pnpm run build` and `pnpm run clean-install` also passed.
The clean install packs OAR and the CLI into a fresh project, checks loading
without the optional SDK, verifies that adding 1.0.38 makes the host compile,
and loads Cursor through the installed CLI. Assertions and timeouts were
not relaxed. The final branch was rebased onto `dac076e`, including the
background-shell live recheck from #428; the complete commit check passed
again after resolving the documentation conflict. Runtime code and dependency
versions were unchanged by that rebase, so the build and packed-install results
above still apply.
