# Claude plan-mode classifier selection, 2026-11-06

Claude 2.1.319 changes the plan/Bash permission path used by OAR's local
provider fixture. With nonessential traffic disabled and no explicit
classifier selection, Bash is denied before any classifier request. The
fixture had assumed the older fallback to the built-in classifier. Its two
severity controls therefore failed, while the remaining 80 Claude vendor
checks passed. Repeating the seven permission checks with 2.1.318 passed.

This is a native behavior change, not a missing `<severity>` match. Captured
HTTP requests contain only the two ordinary model calls on 2.1.319. The
native tool result reports `automode-unavailable`, and the file does not
exist. On 2.1.318, the same fixture records additional classifier requests.

The official [2.1.319 changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#21319)
documents removal of the built-in fallback when telemetry or feature flags
are off, including gateways, and the explicit
`CLAUDE_CODE_AUTO_MODE_SERVER=0` selection. The native controls below verify
that selection in OAR's existing local-provider environment. They do not
test the server-side check, a first-party account or a real model's safety
judgment.

## Native comparison

Linux x64, Node 24.19.0, exact native Claude npm installations. Each row uses
a fresh private workspace, HOME and config, hooks disabled, an empty strict
MCP config, a local scripted Anthropic provider and no account credentials.
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` is set throughout. OAR opens
`--permission-mode=plan` and retains its normal noninteractive permission
configuration. The scripted Bash command writes a marker file using Node.

| 2.1.318 | unset | 90 | 2 | 4 | no | reject, `automode-blocked` |

Every turn completed and no host permission request was sent, including the
denied-tool cases. A completed turn does not imply the tool executed. The
native `tool_result_meta` supplies `non_execution_kind` and
`permission_decision`; the file side effect independently confirms execution.
The severity responses configured in the two unavailable cases were never
requested. [Selected results](2026-11-06.json) omit machine paths and session
identities; raw provider requests and session records remain local.

## Regression and scope

The [vendor suite](../../sea-trial/vendor/claude-permissions.vendor.test.ts)
explicitly selects the built-in classifier only in its two severity
controls. Their positive classifier-call and allow/deny assertions stay
unchanged. Two separate controls leave the switch unset and require zero
classifier calls, no file, a failed tool result and the structured native
`automode-unavailable` rejection. They target the latest 2.1.319 behavior;
the older default remains recorded above rather than accepted as an
alternative result in the new controls.

The adapter and CI installation policy do not change. In particular, OAR
does not opt hosts into the built-in classifier or bypass a native refusal.
The runtime documentation names both paths and preserves the earlier
[2.1.311 observations](README.md). No new permission API is introduced.

## Reproduce

```sh
mkdir -p oar-trial-run/claude-plan
OAR_CLAUDE_BIN=/absolute/path/to/claude pnpm tsx experiments/claude-plan-classifier.ts oar-trial-run/claude-plan/default.json
OAR_CLAUDE_BIN=/absolute/path/to/claude pnpm tsx experiments/claude-plan-classifier.ts oar-trial-run/claude-plan/builtin.json 0
OAR_TEST=claude-aimock OAR_CLAUDE_BIN=/absolute/path/to/2.1.319/claude pnpm vitest run sea-trial/vendor/claude-permissions.vendor.test.ts
```

The [probe](../claude-plan-classifier.ts) runs both severities, writes a
selected JSON summary, and saves raw requests and records alongside it.
Raw output includes local paths and is not intended for publication. The
probe's output argument must have an existing parent directory. Neither
the probe nor the vendor tests use a real model or account quota.

## Validation

The final repository check passed type checking, lint, 3,640 tests and
18 applicable mock behavior cases. Both package builds passed. On Linux,
the complete Claude 2.1.319 vendor run passed all 84 applicable tests,
including the nine permission controls. The seven original controls also
passed on 2.1.318, with the two new-default cases excluded from that older
comparison. The polished probe reproduced the explicit built-in path.
Windows and macOS are left to the new PR's CI; this local report makes no
cross-platform claim.
