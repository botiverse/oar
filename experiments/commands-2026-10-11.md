# Native command discovery: 2026-10-11

`Runtime.commands(installation, { cwd, timeoutMs })` lets hosts populate a
command picker without reading runtime-specific configuration themselves.
This is an independent inventory, alongside skills, MCP servers and tools.
It never submits a model prompt or writes a Session record. Runtime startup
can still load extensions and their native resources.

## Native evidence

| Interface | Evidence and OAR mapping |
|---|---|
| Pi SDK 1.1.0 | `extensionRunner.getRegisteredCommands()` returns the resolved `invocationName`, description and executable handler. `resourceLoader.getPrompts()` returns templates with name, description, optional argument hint, content and provenance. OAR selects metadata only. Its `extension`/`prompt` sources match Pi's own RPC `get_commands` projection. |
| Claude 2.1.296 | Fresh print-mode `initialize.commands`, with no prompt and persistence disabled. The isolated fixture returned 49 entries: native built-ins plus the project's `oar-command`. Entries expose name, description, optional aliases, argumentHint and builtin. OAR preserves metadata; explicit builtin maps to source `builtin`. Other provenance is not inferred from description text. |
| Codex 0.162.1 | The binary's generated `ClientRequest` schema has 170 variants, including skills/list, but no custom-prompt or command-catalog query. Custom prompts are not inferred from the filesystem. The selected app-server interface remains unsupported. |
| Grok 1.0.50 | An isolated `grok inspect --json` reports skills, plugins, MCP servers and other configuration, but no commands field. No independent command reader is added. |
| ACP (Grok, Kimi, OpenCode, Antigravity) | `available_commands_update` belongs to a `SessionNotification` with a required sessionId. It describes a session, not an independent workspace catalog. This reader does not create an ACP session to repurpose that view. |
| Cursor SDK 1.0.37, Pi Durable 1.1.0 | No verified independent command catalog on the selected SDK/Harness interface. Explicit unsupported, as for the existing independent inventories. |

The Pi source distinction and invocation rules are in its published
`core/extensions/runner.js`, `core/prompt-templates.js` and
`modes/rpc/rpc-mode.js`. The ACP notification boundary is in its published
`SessionNotification` and `AvailableCommandsUpdate` types. Native interface
absence here is scoped to those versions and transports, not every way the
vendor's terminal UI can discover commands.

## Observed cases

- Two Pi extensions registering the same name are returned as
  `oar-command:1` and `oar-command:2`. These are the SDK's invocation names,
  not OAR-generated names.
- Pi loads both user and project prompt templates; their descriptions and
  native argument hints survive. A different cwd excludes the project
  template. Template bodies and handlers never enter inventory output.
- Pi skill discovery remains separate and unchanged. Its command reader does
  not add `skill:<name>` aliases or terminal UI built-ins. Extensions load,
  but discovery does not bind startup hooks; a command registered only at
  `session_start` is outside this initial catalog.
- A failing Pi extension leaves the successfully loaded entries available
  with `partial: true`. Prompt and command diagnostics also set partial.
  Their raw messages are not returned. Temporary sessions are disposed on
  success, read failure and late startup after a timeout.
- Claude's project command retains `argumentHint: "<topic>"` and its native
  project-labeled description. It disappears when another cwd is queried.
  One initialize request is sufficient. Account and organization fields are
  excluded, including from results that contain commands.
- Claude's native catalog includes aliases and skill-backed commands, so a
  host merging it with skills must avoid duplicate picker entries. A native
  catalog is not a claim that every command works without UI or starts a
  model turn; OAR neither runs nor emulates a command during discovery.

## Reproduction and validation

```sh
pnpm tsx experiments/commands-native.ts /absolute/path/to/claude
CI=1 pnpm vitest run tests/inventory.test.ts tests/pi/pi-inventory.test.ts
OAR_TEST=pi-aimock CI=1 pnpm vitest run sea-trial/vendor/commands.vendor.test.ts
OAR_TEST=claude-aimock CI=1 pnpm vitest run sea-trial/vendor/commands.vendor.test.ts
oar commands pi --cwd /path/to/project
```

The native probe uses temporary configuration and selects metadata before
printing. Native vendor tests use real Pi and Claude with synthetic resources,
without model requests. They verify workspace scope, collisions, metadata,
partial discovery, unchanged skills and no session/trust persistence.
Protocol tests additionally cover missing/malformed catalogs, timeout
cleanup, aliases, private initialize fields and unsupported readers that
launch no process.

Initial local attempts are retained separately from their corrected runs:
the first standalone Claude probe passed an ignored argument to an
environment helper and therefore read the ordinary configuration (71
commands), without a model prompt; the corrected isolated probe returned 49.
The first Claude vendor test used a relative binary override, which failed
when the inventory changed cwd; the absolute override passed. Initial lint
failures were corrected without weakening behavioral assertions.

Initial local validation passed: 1,686 unit tests, all five behavior backends, the
real Pi and Claude command vendor tests, and the package/CLI build. The
standalone native probe was rerun on the completed implementation. The built
CLI returned the isolated Pi template, argument hint and requested workspace
through `oar commands pi --cwd … --timeout 15000`.

## Windows teardown follow-up

The first Windows Claude vendor run failed removing the command fixture's
working directory (`EBUSY`, CI run 38123476682). The reader already awaited
`child.exited`, but did not request process-tree termination. On Windows an
npm `.cmd` launcher can exit before the native process it launched, leaving
that process or its children holding the directory.

The same missing option was present in four query paths. All now use the
existing `killTree: true` mechanism, as Claude sessions and ACP already do:

- Claude inventories, including skills, MCP servers, tools and commands;
- Claude model listing;
- Claude account-usage control queries;
- Grok inventories (`inspect --json`).

The new vendor fixture also uses the repository's bounded removal retries
(`maxRetries: 10`, `retryDelay: 300`) for transient Windows file locks.
Regression tests pin all four process-tree options and verify that successful,
failed and timed-out inventory reads remain pending until the owned process
exits. The query regression run passed 57 tests; the real Claude command test
passed again on Linux. Windows verification remains the final CI run.

Other process helpers are tracked separately in #352. Empty Claude argument
hints and explicit workspace-code trust guidance are separate follow-ups;
this revision preserves the native command metadata.

## Host compatibility

`CommandEntry` and `RuntimeInventories.commands` are exported by the root and
browser contract entries. `defineRuntime` supplies unsupported for custom
runtimes that do not implement the reader. Manually constructed objects
typed as `Runtime` must add the fourth inventory method. No Session option,
record/event shape or command execution behavior changes. The CLI adds
`oar commands [runtime]` with the existing cwd and timeout options.
