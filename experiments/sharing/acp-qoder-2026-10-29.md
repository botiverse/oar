# ACP and Qoder sharing evidence: 2026-10-29

The current Linux versions have working native concurrent-session transports
and target-only cleanup paths. They are candidates for later integration,
not permission to enable sharing now. In particular, Grok needs session-owned
host terminals and explicit child ancestry; a global connection cannot reuse
the isolated adapter's assumption that any other id is a child. Cross-platform
runs and adapter regressions remain required.

## Scope and method

Linux x64 on xxwork, Node 24.19.0: Kimi 2.4.0, Grok 1.0.70, OpenCode 2.2.1,
Antigravity ACP 1.4.4 and Qoder 1.1.81. ACP uses a scripted local provider;
Qoder uses its own fake-response reader with a synthetic local identity.
Homes and configuration are disposable. No real credentials or paid requests.
This does not reclassify older versions: Qoder <=1.1.80 remains isolated,
and the earlier OpenCode 1.19.5 CPU observation is not a measurement of 2.2.1.

[ACP probe](acp.ts), [Qoder probe](qoder.ts), their fixture/resource helpers,
and [selected values](selected-2026-10-29.json) preserve the observations.
[Run instructions and limitations](README.md) describe output handling.
Antigravity's pinned archive comes from the
[public ACP registry](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json);
the workflow verifies its published digest before extraction.

## Isolation, cancellation and cleanup

Each runtime opens roots A and B on the same native transport, with different
working directories and different `scope.echo` MCP servers. Both model turns
run concurrently. Native command output has the intended directory, MCP output
has the intended marker, and root answer notifications keep their own id.
Antigravity's `run_command` explicitly requires `Cwd`; the probe supplies the
matching session directory, so this checks the configured command path, not an
implicit default-cwd guarantee from that tool.

Both roots then start a real Node parent and child, each held for 60 seconds.
PID plus process-start identity is recorded before cancellation. These identities
only observe liveness; they do not implement native target-only cleanup.

| Runtime | Cancel A | Close A | B before its own cleanup |
| --- | --- | --- | --- |
| Kimi 2.4.0 | A parent and child stop | Native close succeeds | Parent and child still running |
| Grok 1.0.70 | A turn ends, parent and child remain | Native close also leaves them running; disposing A's host terminal owner stops both | Parent and child still running |
| OpenCode 2.2.1 | A parent and child stop | Native close succeeds | Parent and child still running |
| Antigravity 1.4.4 | A parent and child stop | Native close succeeds | Parent and child still running |
| Qoder 1.1.81 | Native interrupt stops A parent and child | `daemon.close_session` succeeds | Parent and child still running |

For Grok, `createAcpTerminalHost` is instantiated **per session** and dispatches
terminal operations only to a known owner. Calling native cancel/close alone
would fail the cleanup gate. The shared process must never be killed just to
release one such session. Other ACP runtimes may use their own command manager;
the probe still provides an isolated terminal host for any client-side terminal.
These experiments cover a root command and its OS child, not every possible
background child-agent workload.

## Child attribution

| Runtime | Native relationship observed |
| --- | --- |
| Kimi | `Agent` runs the child. Its id/result are in the parent session's tool result; no independent child ACP session stream was observed. |
| Grok | The child emits notifications with a distinct session id. Later, the parent's completed tool result names that id in `rawOutput.subagent_id`. Child notifications arrive before that link. |
| OpenCode 2.2.1 | Child text arrives under the root session id with `update._meta["opencode/child-session"]`, including child id, `parentID`, and depth. The tool result also names `sessionID`. |
| Antigravity | Define/invoke runs a child and reaches the local provider. The observed ACP transport exposes its activity through the parent session, not an independent child session stream. |
| Qoder | `task_started.tool_use_id`, nested `parent_tool_use_id`, and `task_notification` link the child to its root's Agent tool call; all retain the root `session_id`. |

On a shared connection, ancestry must use these explicit relationships. A
notification with a different session id is not sufficient. Buffer Grok's early
child notifications, or retain them as unassigned native frames until the
parent link arrives. A link that never arrives must stay unknown.

Grok's `_x.ai/sessions/changed` is also a connection-wide directory broadcast
containing other **root** session ids. Route entries by their own root ids; do
not attach them to whichever root is currently processing a tool. This is a
mandatory Phase 2 routing change with regression coverage. The existing
single-root isolated connection is not changed by these experiments.

## Resume, races and failure

All four ACP runtimes accept a resume/load of an already loaded session; the
next real provider request retains earlier history. The probe reapplies native
mode configuration and verifies a subsequent prompt completes. It did not
request a different model here, so these results do not establish changed-model
override semantics. Those remain subject to the adapter's ordinary model checks.

Concurrent ACP close/resume operations both completed in the observed ordering;
a subsequent explicit resume and prompt also completed. This is a measured
ordering, not exhaustive race verification.

Qoder refuses `daemon.open_session` for the same id while it is still open.
During concurrent close/resume, close succeeded and open refused; a subsequent
serial resume preserved the id and completed a new turn. The pool must serialize
release/reacquire of that identity and treat the refusal honestly, rather than
starting a replacement conversation.

With two model requests held, force-killing the native ACP process closes the
transport and rejects both outstanding prompt requests. Qoder similarly rejects
two active streams after daemon death. These rejection paths include the probe's
transport observers. The future OAR integration still needs one exit record per
owned session and must not restart the pool under surviving handles. Final
fixture cleanup of known crash descendants is separate from per-session cleanup.

## Resources and admission

The resource programs open ten sessions sequentially, execute one concurrent
local-model turn in each, then compare idle process-tree samples. Sequential
opening does not test or fix OpenCode's separate concurrent cold-plugin setup
race. Each row compares the same version/platform and counts native descendants.

| Runtime | Isolated: RSS; CPU; processes | Shared: RSS; CPU; processes |
| --- | --- | --- |
| kimi 2.4.0 | 3334 to 3478 MiB; 46.0 to 56.4%; 10 processes | 381 to 381 MiB; 1.8 to 15.7%; 1 processes |
| grok 1.0.70 | 1228 to 1228 MiB; 0.8 to 1.6%; 10 processes | 158 to 158 MiB; 0.2 to 0.6%; 1 processes |
| opencode 2.2.1 | 3560 to 3569 MiB; 10.6 to 17.2%; 20 processes | 390 to 395 MiB; 2.6 to 5.8%; 2 processes |
| antigravity 1.4.4 | 4945 to 4948 MiB; 1.8 to 3.6%; 20 processes | 2205 to 2207 MiB; 0.2 to 0.6%; 11 processes |
| qoder 1.1.81 | 5080 to 5107 MiB; 76.1 to 89.7%; 20 processes | 451 to 749 MiB; 4.4 to 27.1%; 2 processes |

Antigravity's shared sample still has eleven processes: one ACP front end and
ten native harness processes. It reduces duplicated front ends, not all
session-owned processes. Qoder's shared RSS varies substantially as native
background work settles; Kimi and Qoder also have nontrivial idle CPU.

Every measured shared cohort had lower RSS and CPU than its same-version
isolated cohort during these windows. These are short post-turn samples, not
active-workload CPU or leak tests. The
[previous resource report](../runtime-resources-2026-10-28.md) remains historical;
its values must not be transplanted to a different runtime version.

No native adapter changes in this PR. The manual workflow collects pinned
Linux/macOS/Windows observations after merge; review those results separately.
Until the applicable platform evidence and integration tests are accepted,
`auto` remains isolated and explicit `shared` remains refused for these runtimes.
