### CPU comparison rule

A window that loses processes measures a lower bound: CPU used by the exited
processes is not included. To test whether shared median CPU is no higher,
the isolated lower-bound windows can form a conservative reference. The
true isolated values can only be higher. Shared lower-bound windows cannot
establish that conclusion and are excluded. Exact-window counts must remain
visible, even when the conservative comparison is usable.

Codex Windows has only **1/6 exact isolated windows**, giving 2.36% under the
original rule that excluded lower bounds on both sides. Its shared cohort
has **6/6 exact windows**, median 5.83%. Comparing those exact subsets alone
does not establish the CPU gate. Including all six isolated windows as the
conservative reference gives median 23.95% (five lower bounds, one exact),
so the 5.83% exact shared median is lower. This supports the scoped resource
criterion. A future run will repeat it for confirmation, not erase or replace
this calculation. Codex Linux/macOS have 6/6 exact windows on each side;
Qoder Windows has 3/3 on each side.

The same asymmetric rule applies to later evidence and is recorded in the
[index](README.md). The short idle comparison does not establish active-load
CPU parity or long-running memory stability.
