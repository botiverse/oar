# Windows root identity decision, 2026-10-31

Runtime version check: 2026-10-31

Task #132 is concluded without a production implementation. The tested Node
callback retained a queryable process identity in all six observations. Native
addon and helper options are recorded, but are not being prototyped. Windows
natural-exit orphan cleanup remains a documented limitation. Failed cleanup
after an actual OAR stop action continues to report unverified cleanup; a root
that exits before such an action retains its native result without a new suffix.

## Evidence and reproduction

[Run 41172947472](https://github.com/botiverse/oar/actions/runs/41172947472),
job 124454578883, ran the temporary manual workflow at
`7fd1e3a9804ac015b60d0a912702e4fffea8129e` on Windows x64, Node v24.19.0,
libuv 1.52.1. The step passed. [manifest.json](manifest.json) identifies the
original artifact and hash; [selected-report.json](selected-report.json) is a
byte-for-byte copy of its `report.json`. Unzip that artifact and compare its
`report.json` to reproduce the selection. The full artifact also holds each
fixture's readiness/finish markers and the printed event log.

| Fixture | Native exit code in callback | Native exit timestamp read | OpenProcess error after callback | CIM rows in callback |
| --- | ---: | --- | ---: | ---: |
| normal-0 | 0 | yes | 87 | 0 |
| normal-1 | 0 | yes | 87 | 0 |
| immediate-0 | 7 | yes | 87 | 0 |
| immediate-1 | 7 | yes | 87 | 0 |
| orphan-0 | 0 | yes | 87 | 1 |
| orphan-1 | 0 | yes | 87 | 1 |

No callback CIM read contained the exited root. The two orphan cases each
contained their expected tool, with the recorded parent PID. Normal and orphan
cases read the same native creation identity while alive and inside the exit
callback. The immediate cases also returned their expected exit code 7 and a
completed native exit timestamp. All successfully opened helper handles closed.
The deliberate CIM failure was retained as a failure, and OpenProcess(0)
returned error 87 as expected. No fixture input error occurred.

All six post-callback queries returned OpenProcess error 87. Together with the
pinned Node/libuv source lifecycle, these observations confirm a useful
synchronous callback window in this tested build. They do not make that window
a public Node API contract, identify every other process holding a handle, or
justify carrying the inference across an await. An async JavaScript process
query cannot extend the callback's lifetime guarantee. Blocking synchronous
queries would restore the host stalls removed by task #126.

Thirty-two later fixture creations did not reuse any of the six root PIDs.
Reuse of those root numbers is therefore **missing**, not proved impossible.
Both observed orphan children passed both candidate time filters. That does not
refute the separately labeled synthetic counterexamples: timestamp rounding,
rollback/restoration between samples, and an old owner's surviving child after
reuse remain unsafe bases for attribution. Time intervals authorize no signals.
CIM preserves its returned timestamp precision here; its low FILETIME digits
can differ from GetProcessTimes. Identity matches above compare native readings
to native readings, not rounded CIM values to native ticks.

## Observed query cost

The first complete PowerShell/Add-Type/native/CIM query took 6.399 s.
The remaining 15 ordinary queries took 0.512-0.559 s,
with median 0.522 s. These durations include process startup,
compilation, native reads and CIM. The failure-injection query is excluded from
this range because it deliberately skips CIM. Each query's timing, working set,
CPU and handle count is preserved in the selected report. They measure the
observer, not the marginal cost of retaining a handle or a future helper.

## Decision and restart condition

Cindy reviewed these results and decided not to add a prototype. OAR remains a
pure JavaScript distribution; native dependencies would introduce architecture
builds, packaging, signing and deployment concerns for a less common natural
exit case. Task #131 separately addresses OAR-initiated disposal. This decision
does not claim that all possible JavaScript approaches have been disproved.
It means no supported nonblocking attribution mechanism has been established
by this investigation.

Keep the [options comparison](options.md), source links and experiment branch.
The replacement manual `ci.yml` must not merge. Revisit only when a concrete
user report of natural-exit leakage justifies the added distribution cost.
Before approving a prototype, establish an ownership proof independent of wall
clock intervals, then compare current behavior against a Node-API retained
handle and a host-shared helper. Use the same Windows runner for cold/warm and
one/twenty-root measurements: acquisition and event-loop latency, CPU, peak
working set, handle counts, actual compressed/installed artifact bytes, cleanup
release, immediate exit, helper crash and host exit. Report x64 and arm64
separately; unavailable native arm64 execution remains missing.
