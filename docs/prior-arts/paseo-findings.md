## 1. 抽象层：值得关注的是生命周期契约，而不只是 adapter

- **两层对象：`AgentClient` 管 provider 级发现和资源，`AgentSession` 管一次持久会话。** Client 暴露 create/resume、合并模型和 mode 的 `fetchCatalog`、import/list native sessions、archive/unarchive/shutdown；Session 暴露 `startTurn`、`subscribe`、`streamHistory`、permissions、mode，以及 optional steer/model/thinking/rewind/out-of-band 能力。`run()` 的 convenience 和 event stream 同时存在。[接口，agent-sdk-types.ts:638-802](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-sdk-types.ts#L638-L802)
- **契约区分 close、archive、history resume。** close 仅释放 live runtime，不能删除 durable native session；archive/unarchive 是 Client hooks；`resumeSession(...,{purpose:"history"})` 表示只读历史意图，避免读 archived history 时反向激活真实 agent。`interrupt()` 的成功含义是旧 foreground turn 已不可能继续运行，已 idle 为成功 no-op，只有所有权不确定才 reject。这些语义比统一函数签名更有借鉴价值。[接口注释:646-687、788-802](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-sdk-types.ts#L646-L687)；[archive hooks](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-sdk-types.ts#L788-L802)
- **capabilities + provider-native options + features 三条通道。** capabilities 描述 streaming/persistence/MCP/native tool/rewind 支持；feature 是 toggle/select 供统一 UI 渲染；providerOptions 保持原生语义但经每 provider strict schema 校验，注册表还拥有 exact MCP preapproval 和 tool policy 的映射。不是把不同厂商的 sandbox/approval 字段强行统一。[capabilities:182-202](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-sdk-types.ts#L182-L202)；[registry contract:72-105](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/provider-registry.ts#L72-L105)；[文档 options 边界:5-38](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/docs/providers.md#L5-L38)
- **两条接入路径确已存在。** ACP base 吸收 process/stdin/session/permission 的重复逻辑；direct adapters 接 Claude SDK、Codex app-server、OpenCode SDK、Pi RPC、OMP RPC。registry 工厂实列 Claude/Codex/Copilot/Cursor/OpenCode/Pi/OMP，另含 dev mock；custom provider 能 `extends: "acp"` 配 command，或继承已登记 provider 的配置、模型和 tool-policy contract。[工厂:196-238](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/provider-registry.ts#L196-L238)；[custom registry:755-894](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/provider-registry.ts#L755-L894)。注意 docs/providers 仍称“唯一 built-in ACP 是 copilot”，和本次源码里 cursor 工厂不同；列 provider 时应以当前 registry 为准。

## 2. 事件和身份：统一投影，但保留必要的 native identity

- **统一的是语义流，不是无损 raw-event 总线。** `AgentStreamEvent` 是 thread/turn/usage/permission/timeline/provider_subagent 的 discriminated union；`AgentTimelineItem` 统一 user/assistant/reasoning/tool/todo/error/compaction/plugin。类型上没有一个必须保存 native envelope 的 `raw` 字段；tool detail 可带 metadata，但不能据此宣称全事件保真。Paseo 更偏 UI/daemon 的语义投影，native history 仍由 adapter 恢复。[事件完整 union:404-475](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-sdk-types.ts#L404-L475)
- **wire user id 和 provider user id 分开。** Manager 在接受用户提交时写 canonical row，以 clientMessageId 建幂等身份，native echo 补充 providerMessageId 而不重复新增；rewind 转换回 native message id。在同一次用户提交的 provider echo 可能先于 `startTurn` 返回的竞态下仍有显式 reconcile。不要用正文字符串全局去重。[record/reconcile:4473-4515](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-manager.ts#L4473-L4515)；[rewind:3005-3020](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-manager.ts#L3005-L3020)
- **turn 还需要本地 run token。** `AgentRunState` 区分 PendingForegroundRun 和 AutonomousAgentRun，前者含本地 token、pending/started/failed、stagedEvents，后者用于 provider 自发继续工作；terminal settle 对 native turnId 精确匹配。这避免“旧 turn 迟到 terminal 结束新 turn”以及 start acknowledgement 前事件到达的竞态。[agent-run-state.ts:5-105](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-run-state.ts#L5-L105)

## 3. 多 provider 与 autonomous multi-agent 都有，但分层明确

- **Paseo managed child 是完整独立 agent。** 统一工具目录注册 `create_agent` 和 `send_agent_prompt`，agent scoped create 默认 caller workspace/成为 subagent，后台执行并通过通知回父 agent；send 的默认 background/notifyOnFinish 随 caller 身份决定。它是跨 provider 的委派基础设施，任务拆解/角色分配依旧由调用它的 agent 决定，不是框架固定 DAG scheduler。[create tool:1406-1424、1510-1529](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/tools/paseo-tools.ts#L1406-L1424)；[send tool:1868-1908](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/tools/paseo-tools.ts#L1868-L1908)
- **工具目录与 MCP 分开。** Manager 根据 `supportsNativePaseoTools` 注入已按 caller policy 过滤的原生 catalog；若注入原生工具则去掉内部 MCP server，避免重复暴露同一工具。因此 MCP 是一个 transport adapter，而不是 orchestration 业务的唯一位置。[agent-manager.ts:5024-5042](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-manager.ts#L5024-L5042)
- **通知不是一次 wait promise。** `setupFinishNotification` 维护订阅、permission request 去重和串行 notification queue；将子 agent 最后消息作为 system notification，以 steer 发给 caller；parent 已归档则不唤醒。permission 是中间 checkpoint，不能收到一次 permission 就解除最终完成订阅；测试显式覆盖“finish notifications survive permission responses”。[agent-prompt.ts:385-479](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-prompt.ts#L385-L479)；[回归测试:311 起](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-prompt.test.ts#L311)
- **managed child 与 provider-native subagent 是双身份系统。** Claude/Codex/OpenCode native child 通过独立 `provider_subagent` 事件和 `ProviderSubagentStore` 管 descriptor + timeline，key 是 managed parentId 与 native childId 的复合键，另有 parentSubagentId 保留嵌套拓扑、toolCallId 关联启动工具。Manager 对这类事件单独 dispatch 后 return，不把它当 managed root turn terminal。native 子会话在 UI 通常只读，不能假装拥有完整 AgentSession 控制权。[store.ts:11-67](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/provider-subagents/store.ts#L11-L67)；[manager 分流:3656-3662](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-manager.ts#L3656-L3662)。例外是 OMP provider-managed child handle 可导入完整 managed record，provider 仍拥有底层 runtime（见 [docs/provider-managed children](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/docs/agent-lifecycle.md)；本条例外只核对了文档，未深入跟踪完整导入实现）。
- **parent relation 不等于 workspace ownership。** 归档 parent 遍历 parent label，仅对仍有归属的 child 做 lifecycle mutation；显式策略选择 detach 或 cascade archive。由此可以跨 workspace 委派，同时不会把同目录 `cwd` 误当所有权键。[cascade:1713-1755](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-manager.ts#L1713-L1755)

## 4. 测试层要按“替换边界”来读

| 层 | 实际替换边界 | 能证明什么 / 不能证明什么 |
|---|---|---|
| provider mapper/unit | 直接输入原生 SDK message、notification 或历史记录 | 证明语义投影和归属规则；不覆盖真实进程 |
| adapter + native-protocol fake | Codex 替换 spawn，假 child 用 PassThrough stdio；Claude 注入 queryFactory；Pi/OMP 注入其 typed runtime；OpenCode 注入 ServerManager/SDK client | 仍执行真实 AgentClient/Session，可验证命令参数、native event→统一 event、permission/interrupt；各 provider 的 fake 粒度不统一 |
| daemon integration（不少命名为 .e2e） | 顶层 `AgentClient` 整体替换为 `FakeAgentClient` | 跑真实 daemon/WebSocket/磁盘/manager/客户端；**不能**当成真实 provider mapper 验证 |
| real provider contract | 显式注入 `createRealProviderClient` | 真 CLI/SDK 和真实模型；独立脚本，允许按可用性 skip |
| browser | 普通 browser project 多用 dev `mock` provider；real-provider 是独立 project | 可分别验证 UI contract 和真实 provider 的用户路径 |

## 6. 对 OAR 最值得迁移的设计与警惕项

1. 将 interrupt 的“旧 turn 确定失去执行权”写成接口契约；本地 run token + native turnId 双重约束，并测 start ack 前事件、迟到 terminal、rejected interrupt 后不能启动替代 turn。
2. 把 user client id/native message id、managed agent id/provider-native subagent id 分开，原生 child flow 不得结束 managed parent；补充嵌套子 agent、unmapped foreign thread、后台 child 在 root turn 完成后继续输出的回归。
3. replay 与 live 收敛到同一 observation/reducer 层；强调拓扑和 terminal sticky merge 的一致性，而不只是最终正文一致。
4. 编排工具目录独立于 MCP transport，按 provider 能力走 native tools 或 MCP；policy 用 caller/child 各自明确作用域，避免父 agent policy 意外传播。
5. 测试清单按 execution boundary 分类：manager-fake、native-protocol-fake、real-provider contract、UI mock、UI live；每类写清 CI 是否执行、跳过原因。Paseo 的教训是 `.e2e` / `live` 命名本身不足以判断覆盖。
6. 可选方法 + 手写 wrapper 会增加维护风险。例如本次 `AgentSession.steerActiveTurn?` 已在接口出现，但 `wrapSessionProvider` 的逐项委托对象没有转发该方法；这是源码静态观察，未运行复现。对 custom/derived provider 的新增能力需要 wrapper parity 测试，不能只测 built-in adapter。[interface:665-669](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/agent-sdk-types.ts#L665-L669)；[完整 wrapper:444-477](https://github.com/getpaseo/paseo/blob/1f5b6143d603ebecc678daf76d407938175be044/packages/server/src/server/agent/provider-registry.ts#L444-L477)
