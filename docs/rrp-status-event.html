Agent lifecycle: status is fold(events)

oar RRP · the status↔event derivation, first-principles · the model behind the #840 "wrongly-terminal" fix

The events are the primary facts. Status is not a field a runtime sets — it is a pure projection the host computes.
status = fold(events)

There is no set_status in the protocol — only emit_event. Status is recomputed from the event prefix every time.

The design axis — two masters, one mechanism

A runtime protocol serves two sides at once, and they pull in opposite directions: a clean typed union is easy for the consumer but risks dropping producer detail; raw passthrough keeps everything but is unconsumable. The resolution is to give every event two faces.

envelope → for the CONSUMER

semantic clarity

The common, typed meaning — the only thing fold → status ever reads. Same envelope sequence folds to the same status on any runtime. Easy to consume.

payload → for the PRODUCER

lossless

The runtime's raw detail, carried verbatim on the event. The normalizer only decides which envelope a raw event means; it drops nothing. No raw with nowhere to go ⇒ no untyped catch-all.

Neither side taxes the other: the consumer folds only envelopes (clean, cross-runtime stable); any producer detail is recoverable from the payload (lossless).
Producer-lossless and consumer-clear are each an acceptance criterion: raw must round-trip from the event stream · the same envelope sequence must fold to one status on every runtime.

The event union: turn_started · tool_call · tool_result · turn_end{completed | interrupted | crashed} · runtime_error. Status ∈ idle · thinking · tool-executing · stopped · crashed — each a function of the prefix.

Two levels — never merged

process lifecyclestatesfolds from
the daemon's view of the OS process launching · running · stopped · crashed residency + process-level events
turn lifecyclestatesfolds from
what's happening inside a running process idle · thinking · tool-executing · turn-end in-process turn events

running process + idle turn is a legal, common state. Collapsing the two levels loses exactly that distinction.

crashed ≠ completed — the silent-failure test

completed the process produced a turn_end{completed}.

crashed the process ended having never produced one — "alive but emitted nothing" is detectable.

An independently-set done flag can't tell a clean finish from a crash that happened to flip it. Only the derived projection can.

Why derived, not a field of its own

independent status

Can silently disagree with the events — status says idle while an un-closed tool_call says otherwise. Nothing forces the field false, so the drift is invisible.

derived status

Cannot drift — recomputed from the facts every time. So the derivation function itself is the contract, shipped with the event union, not a status enum each vendor fills in.

The concrete stakes — #840 (agents wrongly marked terminal)

Marking an agent terminal is a status bug whenever terminal is set independently rather than folded from events.

A recoverable remote-compaction / provider-capacity failure is not agent-terminal — but a hand-set flag makes it so, and the process is killed.

First-principles fix (the rule above): terminal/crashed must fold from the event stream, and a retriable failure event must not fold to terminal — it folds to a backoff / fallback state instead.

Anchor: raft packages/daemon/src/runtimeTurnState.ts — the normalizer decides which raw event means turn-started / tool-boundary, and RuntimeTurnState "owns only the derived state budget." Status is downstream of events, never a peer of them.
