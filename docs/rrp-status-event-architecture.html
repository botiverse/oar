components · data flow · boundaries · where the #840 fix lives

1 · The pipeline, by boundary

Three swim-lanes: what the runtime vendor owns, what the oar RRP contract fixes, what the host/consumer owns. Raw flows down; nothing is set upward.

PRODUCER
(runtime side)
runtime process
codex / claude / kimi / …
→
raw output
stdout / app-server / SDK events
→
normalizer (driver)
raw → which envelope? · keep raw as payload
oar RRP
(the contract)
EVENT UNION (envelope + payload)
turn_started · tool_call · tool_result · turn_end{completed|interrupted|crashed} · runtime_error
→
fold(events)
pure projection over the prefix · the shipped contract
CONSUMER
(host side)
status
idle/thinking/tool/stopped/crashed
→
UI
reads only the envelope-derived status
lifecycle decisions
restart / retry / mark terminal
task / activity log

Direction is one-way. The producer only emit_events; the consumer only folds. No component writes a status back — so a consumer and the events can never disagree.

2 · Anatomy of one event — the two faces

Every event carries a typed envelope (what the consumer folds) and a verbatim payload (what keeps the producer lossless). One object, two masters.

envelope consumer · semantic

kind: tool_call
seq: 41
at: 2026-08-11T01:02:03Z

common, typed meaning · fold reads only this · stable across every runtime

payload producer · lossless

raw: { … vendor-specific … }
tool: "bash", args: {…}
source_line: 883

runtime's raw detail, verbatim · nothing dropped · no untyped catch-all needed

3 · Two folds, two levels

Each level folds its own events. A running process with an idle turn is legal — merging the levels would erase that.

process lifecycle — folds residency + process events

launching→ running→ stopped crashed

turn lifecycle — folds in-process turn events

idle→ thinking⇄ tool-executing→ turn-end

crashed ≠ completed: crashed = process ended with no turn_end{completed} ever emitted — the silent-failure case only a derivation can see.

4 · Where #840 lives — the terminal decision

The bug: terminal set independently — a recoverable capacity / remote-compaction failure gets flagged terminal and the agent is killed.

The fix moves the decision INTO the fold:

runtime_error / capacity
→
fold: is this event retriable?
→
retriable → backoff / fallback (process stays alive)
genuinely terminal → crashed / stopped

terminal/crashed are outputs of the fold, never inputs. A retriable failure event must not fold to terminal. (The rate-limit datapoint: an account-level capacity error is transient — exactly the event that must survive, not kill.)
